# Документация (mdBook)

Книга лежит в `docs/src`, оглавление - `docs/src/SUMMARY.md`. Собирается mdBook.

## Структура книги

Одна книга на https://brokapi.ru/docs/. Общее написано один раз, у каждого продукта свой раздел:

```text
install.md                   Установка: cargo add, pip install, из репозитория, проверка, частые ошибки (часть «Начать»)
README.md                    Что это: развилка из четырех карточек (Rust, Python, Gateway, CLI)
architecture, streams, orders, reconcile, limits, numbers    Как устроено (общее)
brokers/                     Брокеры (общее)
rust/                        Rust: index.md, быстрый старт и инструкции (работает сейчас)
python/                      Python: index.md, быстрый старт, инструкции, тесты, объяснение (работает сейчас)
gateway/index.md             Gateway: заглушка (служба и командная строка brokapi)
cli/index.md                 CLI: заглушка, стадия "к бете" (командная строка brokapi)
agent-contract, errors, events, coverage    Справочник (общее)
api.md, api-python.md, api-gateway.md       Справочник API: Rust (rustdoc в api/), Python (pdoc в api/python/), Gateway - заглушка
before-live                  Перед боевым счетом (часть «Начать»)
changelog                    Версии: изменения по выпускам
agents/unverified.md         Допущения по документации брокеров, только для ИИ-агентов: в SUMMARY.md нет, в HTML не собирается, попадает в llms.txt, llms-full.txt и python/llms.txt через docs/llms.py
```

- **Новая страница продукта** кладется в его папку, строка добавляется в `SUMMARY.md` в части этого продукта и в
  `DESCRIPTIONS` в `docs/llms.py` (без строки сборка падает). Ссылки внутри книги пишутся на `.md` и относительные:
  из `rust/` на общее - `../errors.md`.
- **Страницу переносят - старый адрес должен жить.** В `book.toml` в `[output.html.redirect]` добавляется строка
  `"/старый.html" = "новый/путь.html"`. mdBook кладет на старое место страницу с переадресацией (сохраняет `#якорь`),
  а `docs/llms.py` по этой же таблице пишет старый `страница.md` с адресом нового. Сайт и внешние ссылки тогда не ломаются.
- **Заглушка** (продукт, которого еще нет) - один компонент `.stub` из `theme/brokapi.css`, образец - `gateway/index.md`.
  Заголовок продукта, метка стадии (`stub-stage`: "К бете" или "Возможно"), строка о том, что этого еще нет, три блока:
  "Что это будет" (2-4 строки), "Что работает уже сейчас" (ссылки на общие страницы, верные и для этого продукта) и
  "Как узнать, что появилось" со ссылкой на "Изменения" (`stub-foot`). Между HTML-тегами оставляйте пустые строки:
  тогда внутри работает обычный markdown. Не обещайте того, чего нет в решениях. Когда продукт выходит, заглушка
  заменяется настоящими страницами, а в `llms.py` пропадает пометка "ЕЩЕ НЕТ" в `DESCRIPTIONS` и в `SECTION_NOTES`.
- **Код на нескольких языках (вкладки Rust / Python / gRPC).** Парные блоки оборачиваются в `<div class="lang-tabs">` (пустые
  строки вокруг и внутри). Код для каждого языка берется из файла, который запускает тест: Rust - из `examples/`, Python - из
  `crates/python/examples/` (`{{#include ...:якорь}}`). Не пишите код вкладки руками прямо в странице, иначе он не будет тестом.

  ````text
  <div class="lang-tabs">

  ```rust,ignore
  {{#include ../../examples/contract.rs:unknown}}
  ```

  ```python
  {{#include ../../crates/python/examples/rules.py:unknown}}
  ```

  </div>
  ````

  Скрипт `docs/lang-tabs.js` (подключен в `book.toml`, `additional-js`) находит `.lang-tabs`, по классу `language-*` собирает кнопки и
  прячет все блоки, кроме выбранного. Выбор языка запоминается и общий для всей книги. Без скрипта блоки стоят друг под другом с
  подписью языка (`theme/brokapi.css`). Блок кода с `{{#include ...:якорь}}` внутри функции попадает в книгу с отступом: препроцессор
  `docs/dedent_code.py` (после `links`) снимает общий отступ, иначе пример на Python нельзя копировать.

```bash
mdbook build docs      # только книга, результат в docs/book (в git не попадает)
mdbook serve docs      # локально на http://localhost:3000 (справочника API здесь нет)
docs/build.sh          # книга + индекс поиска (Pagefind) + справочник Rust (rustdoc) в docs/book/api/ + справочник Python (pdoc) в docs/book/api/python/
tools/check            # проверка перед пушем: fmt, clippy, тесты, примеры, rustdoc, книга
```

## Справочник API и примеры

Справочник по методам, типам, полям и ошибкам не пишется руками: он собирается из комментариев `///` и `//!` в коде
(rustdoc, на английском, потом уйдет на docs.rs). Книга объясняет и учит, на методы ссылается в справочник и их не
пересказывает.

- **Каждый пример - тест.** Примеры в `///` идут через `cargo test --doc`, длинные сценарии лежат в `crates/*/examples/` и в `examples/` корня (код книги) и
  собираются `cargo build --examples`, а программы корня еще и запускаются тестом `tests/examples.rs`. Все они ходят не в сеть, а в имитацию брокера из крейта `brokapi-mocks`
  (БКС, Т-Банк, Финам). Подготовка имитации в doctest спрятана строками `# `, читатель видит только то, что напишет сам.
  Сломался пример или не сходится ссылка - падает сборка.
- **Примеры из `examples/`** по умолчанию идут против имитации. Настоящий брокер включается переменной окружения
  `BROKAPI_LIVE=1` (настройка берется из `.env`).
- **`tools/check`** (bash) гоняет семь шагов по порядку: `cargo fmt --all --check`,
  `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `cargo test --doc --workspace`,
  `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --workspace --features brokapi/bcs,brokapi/tbank,brokapi/finam,brokapi/alor`, `cargo build --examples`, `mdbook build docs`.
  Останавливается на первом упавшем. Запускайте перед пушем. CI пока нет, этот скрипт и есть проверка.
- **`docs/build.sh`** собирает книгу в `docs/book.new`, rustdoc (`cargo doc --no-deps` без `brokapi-mocks` и служебных
  крейтов) кладет в `docs/book.new/api/`, и только после успеха подменяет `docs/book`. Сломанная сборка оставляет прежнюю
  версию. Сайт документации собирается именно этим скриптом, а не голым `mdbook build docs`. Нужны `mdbook`, `mdbook-mermaid`,
  `pagefind` (бинарь версии 1.5 или новее, либо `npx`, который его скачает) и Rust. Без `pagefind` сборка падает: поиска не будет.
  Собрать без поиска можно с `BROKAPI_NO_SEARCH=1`.
- Крейт `brokapi-mocks` - только для тестов и примеров, не часть публичных обещаний библиотеки. Имитации написаны по документации
  брокеров и не доказывают, что настоящий брокер отвечает так же.

Что важно знать:

- **Покрытие API** - страница книги `coverage.md`. Она собирается скриптом по коду и руками не правится.
- **Предупреждение «на настоящих счетах не запускали»** стоит в трех местах: страница `before-live.md`, врезка в быстрых
  стартах и раздел «Что учесть» на странице брокера там, где это меняет код бота. В остальных местах - «по документации
  брокера» или ничего.
- **Схемы Mermaid** рисуются в браузере из локальных файлов `docs/mermaid.min.js` и `docs/mermaid-init.js`, сеть
  не нужна. Библиотеку ставит `mdbook-mermaid install docs` (бинарь `mdbook-mermaid` лежит рядом с `mdbook`, препроцессор
  подключен в `book.toml`). Обновить библиотеку схем - запустить ту же команду заново, вернуть свой `mermaid-init.js` и закоммитить файлы.
- **Вид книги - дизайн «Спецификация»** (как сайт brokapi.ru).
  Белая холодная страница, текст `#0b1220`, синий `#1f3fe0` для ссылок и активного пункта, оранжевый только как сигнал (точка знака,
  квадрат стадии, активная вкладка листинга), код темными блоками, темная тема `coal` в тех же холодных тонах. Файлы лежат в `docs/theme/`:
  `index.hbs` (взят из `mdbook init --theme` версии 0.5.4: в шапку добавлены знак и слово brokapi со ссылкой на https://brokapi.ru/ и
  пункт «Документация», строка ревизии под шапкой, внизу страницы две карточки «Назад» и «Дальше», пустая колонка «На этой странице»,
  строка «brokapi by RunInfra»), `brokapi.css` (токены и все компоненты), `favicon.svg`, шрифты в `theme/fonts/`. Шрифты только со свободной
  лицензией: IBM Plex Sans и IBM Plex Mono (OFL, текст лицензии рядом), страница не делает внешних запросов. Текст строки ревизии
  (версия и стадия) записан только в `index.hbs`, меняется там при смене стадии. По умолчанию светлая тема, темная включается в меню.
  Цвета схем - в `docs/mermaid-init.js`: он свой, поэтому после `mdbook-mermaid install docs` его нужно вернуть
  (`git checkout docs/mermaid-init.js`). Справочники API (rustdoc и pdoc) в тех же цветах и шрифтах, по умолчанию светлые:
  rustdoc берет `docs/rustdoc-brokapi.css` (`--default-theme=light` и `--extend-css` в `docs/build.sh`), pdoc - `docs/reference/custom.css`,
  общая полоса сверху - `docs/reference/bar.html`.
- **Навигация.** Карточки «Назад» и «Дальше» (`<nav class="pager">` в `theme/index.hbs`, названия из `{{previous.title}}` и `{{next.title}}`)
  идут по плоскому порядку `SUMMARY.md`, поэтому последняя страница раздела ведет в следующий. Если страница по ту сторону в другой части
  книги, подпись карточки говорит об этом («Следующий раздел: Rust», это делает `docs/ui.js` по частям меню). Боковые стрелки mdBook
  скрыты стилем, но остались в разметке: клавиши Влево и Вправо нажимают именно их (`book.js`). Разделы меню слева сворачиваются
  (`[output.html.fold]` в `book.toml`), раскрыт тот, где открытая страница. Колонка «На этой странице» справа от текста строится
  в `docs/ui.js` из заголовков `h2` и `h3`, показывается на экране шире 1240 px, на узком те же заголовки лежат в меню слева.
- **Поиск по-русски - Pagefind.** Встроенный поиск mdBook выключен (`[output.html.search] enable = false` в `book.toml`): его
  индекс режет все не-ASCII буквы. После `mdbook build` скрипт `docs/build.sh` запускает `pagefind --site docs/book.new --force-language ru`,
  индекс ложится в `docs/book/pagefind/` и грузится только при первом поиске. Индексируется `<main data-pagefind-body>` каждой
  главы (`theme/index.hbs`), схемы (`pre.mermaid`) и страница печати не индексируются. Окно поиска - `docs/search.js` (клавиши
  `/` и `s`, Esc), вид - в `theme/brokapi.css`. Проверка: запросы заявка, лимиты, сверка, стакан, токен, таймаут, Т-Банк, неизвестно,
  Unknown, cid, БКС, Python, reconcile, количество, лот находят нужную страницу.
- **Схемы грузятся только там, где они есть.** `theme/index.hbs` не подключает `mermaid.min.js` (2,7 МБ), а кладет его адрес в
  `<script type="text/plain" id="mermaid-lib">`, `mermaid-init.js` подгружает файл, если на странице есть `pre.mermaid`, и ждет шрифт перед отрисовкой.
- **Один язык на весь сайт.** Переключатель Rust и Python в шапке и вкладки на страницах - `docs/lang-tabs.js` (ключ `brokapi-lang` в
  `localStorage`, тот же, что на сайте). Пары страниц Rust и Python (`TWINS` в начале файла) предлагают перейти к странице на другом языке.
  Одиночный блок кода на общей странице подписывается языком (`Rust`), если рядом нет вкладок. Вкладки имеют роли `tablist`, `tab`,
  `tabpanel`, стрелки внутри таб-бара не листают главу. У страниц Rust и Python разные названия в `SUMMARY.md` и в заголовках.
- **Мелочи интерфейса - `docs/ui.js`:** таблицы из трех колонок и больше на телефоне (до 700 px) становятся карточками (подпись колонки берется из
  заголовка и ставится как `data-label`), широкие таблицы на компьютере листаются с закрепленным первым столбцом и подсказкой, все,
  что листается вбок (таблица, код, схема), получает `tabindex` и имя, код длиннее 45 строк складывается в `<details>` с ограничением
  высоты (от 120 строк закрыт), кнопка копирования видна на касании и по фокусу и называется по-русски, кнопка «Сообщить об ошибке»
  внизу страницы открывает форму (`<dialog>`), отчет уходит POST-запросом на `/api/report` того же хоста (приемник на сервере,
  не в этом репозитории), адрес получателя читатель не видит. Ссылка «К содержимому» и роль `banner` - в
  `theme/index.hbs`.
- **Справочники API (rustdoc и pdoc) с шапкой книги.** Шапка (знак, `docs`, «В книгу», переключение между справочниками Rust и Python,
  тема) лежит в `docs/reference/bar.html`, ранняя установка темы по `localStorage` `mdbook-theme` - в `docs/reference/head.html`. rustdoc
  получает их флагами `--html-before-content` и `--html-in-header` (`docs/build.sh`), pdoc - через `docs/reference/frame.html.jinja2`
  (`docs/pydoc.py`, `template_directory`). Стили pdoc - `docs/reference/custom.css`, rustdoc - `docs/rustdoc-brokapi.css`.
- **Адрес: https://brokapi.ru/docs/.** Папка `docs/book` - это корень `/docs/`: книга лежит в ней, справочник в `api/`
  (`/docs/api/`), файлы для агентов рядом (`/docs/llms.txt`, `/docs/llms-full.txt`, `страница.md`). Все ссылки внутри
  относительные, в `book.toml` стоит `site-url = "/docs/"` (от него строятся `404.html` и поиск), шрифты справочника
  берутся по пути относительно `api/theme.css`. Ссылки для агентов в `llms.txt` строит `docs/llms.py` от адреса
  `https://brokapi.ru/docs` (переменная `BROKAPI_DOCS_URL` меняет его).
- Примеры кода на Rust в книге собирались против текущего кода. После изменения публичного API их нужно проверить
  заново.
