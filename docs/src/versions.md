# Совместимость и версии

Объяснение: что меняется от выпуска к выпуску, что обещано не меняться и как зафиксировать версию у себя. Что именно поменялось в каждом
выпуске - [Изменения](changelog.md).

## Один номер на все

Крейты на crates.io, пакет `brokapi` на PyPI, программа `brokapi` в выпусках GitHub и модуль Go выходят одним номером. Номер на PyPI записан
по правилам Python (`{{brokapi_version_py}}` вместо `{{brokapi_version}}`), модуль Go - тегом `go/v<номер>`. Берите все части одного номера: имитации
(`brokapi-mocks`) и коннекторы одного выпуска знают друг друга, бот на Python и гейтвей одного выпуска говорят на одном `.proto`.

## Что обещано до беты

Сейчас открытая альфа. Обещания разные для разных частей, потому что у них разные пользователи.

| Часть | Обещание | Почему |
|---|---|---|
| gRPC гейтвея, пакет `brokapi.gateway.v1` | только дополняется: новые вызовы, поля, значения перечислений. Вызовы и поля не удаляются, номера полей не меняются и не переиспользуются, смысл поля не меняется. Ломающее изменение - только новым пакетом `v2` рядом с `v1` | клиент на другом языке сгенерирован из `.proto` и обновляется отдельно от программы: старый клиент должен работать с новым гейтвеем |
| Rust (`brokapi`, `brokapi-*`) и Python (`brokapi`) | могут меняться в любом выпуске альфы | интерфейс еще ищем, и правка по жалобе пользователя важнее совместимости. Каждое ломающее изменение записано в [Изменениях](changelog.md) с тем, что поменять в своем коде |
| Имитации `brokapi-mocks` и сценарии `brokapi-conformance` | могут меняться в любом выпуске, и после беты тоже | это инструменты тестов: рычаги добавляются, когда появляется сбой, который стоит проверять |
| Конфиг `brokapi.toml` и команды программы | могут меняться в любом выпуске альфы, неизвестный ключ - ошибка конфига, а не молчание | ошибка при старте лучше, чем гейтвей, который тихо делает не то |

После беты обещания для Rust и Python станут строже, это будет записано здесь.

## Как зафиксировать версию

В альфе берите точный номер, иначе обновление зависимостей может принести другой выпуск альфы:

```toml
# Cargo.toml. Без "=" cargo считает следующий выпуск альфы подходящей заменой.
brokapi = { version = "={{brokapi_version}}", features = ["tbank"] }
```

```text
# requirements.txt
brokapi=={{brokapi_version_py}}
```

Программу `brokapi` ставьте файлом конкретного выпуска со страницы выпусков или `cargo install brokapi-gateway --version {{brokapi_version}} --locked`.
Какой номер работает, печатает `brokapi --version`. Сборка из `main` добавляет к номеру коммит, так она отличается от выпуска ([Установка](install.md)).

## Как обновляться

1. Прочитать в [Изменениях](changelog.md) разделы выпусков между вашим и новым, пункты «Что поменять».
2. Поднять номер у всех частей сразу: библиотеки, программы, имитаций.
3. Прогнать свои тесты на имитациях нового выпуска, потом бота на песочнице или демо-счете.
4. Программу на сервере - по разделу «Обновить программу» в [Запуске и обслуживании](gateway/operations.md).
