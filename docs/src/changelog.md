# Изменения

Что появилось в библиотеке и что поменять в своем коде. Новое сверху.

## 0.1.0-alpha.10: завершение Python и восстановление соединений

- **БКС и АЛОР: пауза после ошибки восстановления подписки.** При обрыве записи повторное подключение теперь соблюдает
  растущую паузу, как при обычном обрыве потока. Раньше эта ветка могла открывать следующие соединения без ожидания.
- **Имитации Rust:** `brokapi_mocks::io::FaultyWrite` прерывает запись после заданного числа байтов, возвращая `BrokenPipe`.
  Рычаг подходит для проверки частично отправленных кадров и команд в собственном коде на Tokio.
- **Справочник Rust:** опубликованы типы `brokapi-mocks`, пример и методы I/O-рычага доступны и в текстовом справочнике.
- **Go: подключение после смены порта гейтвея.** `Connect` перечитывает `gateway.addr`, пока ждет готовности. При перезапуске гейтвея
  на Windows клиент больше не ждет весь таймаут по старому адресу.
- **Имитация гейтвея:** `mock.start_gateway(limits_toml=...)` принимает собственные лимиты в TOML. Это позволяет проверять общий бюджет ботов
  с заданной квотой и периодом пополнения, без зависимости от скорости компьютера.
- **Python завершает фоновые задачи до остановки интерпретатора.** Раньше бот мог напечатать успешное завершение, а затем аварийно упасть:
  при финализации Python оставались фоновые потоки. Асинхронный мост теперь владеет своим runtime и останавливает его при выходе.
- **Заготовка бота:** `python bot.py --mock` изолирован от настоящего `.env`, токенов и торговых ограничений. Режим только чтения из `.env.example`
  больше не заставляет демонстрацию бесконечно ждать покупку. Ошибка стратегии завершает демонстрацию с ошибкой, ожидания ограничены.
  `python bot.py --help` показывает справку, неизвестные аргументы отвергаются до подключения.

## 0.1.0-alpha.9: бот через ИИ-агента, имитации на crates.io, история без пропусков

- **Бот через ИИ-агента.** Страница [Бот через ИИ-агента](agent-setup.md): текст, который человек отдает своему агенту, и порядок работы агента
  с тремя остановками (вопросы, токен, настоящий счет). Начинают с нее `llms.txt`, README и описание на PyPI. На сайте - вкладка «ИИ-агент».
- **`python -m brokapi new my-bot --broker tbank`** создает готовый проект: бот с сигналом, покупкой и стоп-заявкой после исполнения, его тесты на
  имитации, `.env.example` с режимом только чтения и потолком заявки, `AGENTS.md` с правилами для агента, `README.md`. Для каждого из пяти брокеров
  тест создает проект и прогоняет его тесты и `python bot.py --mock`.
- **Bybit: история свечей больше не теряет бары.** Биржа считает оба конца диапазона и отдает новые бары первыми, поэтому полное окно в 1000 баров
  приходило 1001 баром, предел отрезал самый старый, и у каждого полного окна пропадал первый бар: за 100 дней часовых баров 2398 вместо 2400, без
  ошибки. Теперь конец окна запрашивается на миллисекунду раньше. Тест истории на всех пяти брокерах проверяет каждый бар периода.
- **Python: `candle_pages(..., window=timedelta(...))` работает.** Раньше любое окно давало `TypeError: a float cannot be exact`. Окно - целые секунды,
  не меньше одной, иначе `ValueError` до чтения. Ключ `window_secs` неверного типа в вызове по имени теперь ошибка, а не молча игнорируется.
- **`brokapi-mocks` и `brokapi-conformance` на crates.io.** Имитации для своих тестов на Rust: `brokapi-mocks = "<тот же номер, что brokapi>"` в
  `[dev-dependencies]` вместо пути к клону. Сценарии `brokapi-conformance` проверяют свой коннектор. Интерфейс обоих может меняться в любом выпуске.
  [Тесты против имитаций, Rust](rust/mocks.md) с полным тестом «заявка -> исполнение», [Свой брокер](brokers/own.md).
- **Обещание совместимости до беты:** gRPC `brokapi.gateway.v1` только дополняется, Rust и Python могут меняться, каждое ломающее изменение - здесь.
  [Совместимость и версии](versions.md).
- **Книга:** [Платформа на много клиентов](gateway/many-clients.md), [Свой брокер](brokers/own.md). Страница истории говорит, какой токен нужен для живой
  выгрузки и что имитация годится для кода, а не для стратегии. Файл `history.py` пишет CSV со строкой заголовка, `read_bars` читает его с `Decimal`.
  У БКС `close_ts` свечи равен `open_ts`, это теперь сказано там, где книга учит отличать закрытый бар.
- **docs.rs** показывает модули брокеров (`brokapi::tbank` и другие): документация собирается со всеми флагами. Описание крейта и README называют Bybit.
  Пакет `brokapi` на crates.io больше не несет `examples/` и `tests/`, которые без репозитория не собирались.
- **`brokapi add`** отвечает `starting` про гейтвей, который запускается, а не `stopped`. Ошибка неизвестного брокера в Rust называет и `bybit`.

## 0.1.0-alpha.8: песочница Т-Банка из Python, Финам без номера счета, бот с сигналом и стопом

- **Счет песочницы Т-Банка из Python.** У нового токена песочницы счетов нет, и `connect` отвечал `Config`, а открыть счет было нечем: `raw` требует
  подключенного клиента. Теперь `await brokapi.open_tbank_sandbox_account(money="100000", sandbox=True)` открывает счет и пополняет его, в Rust -
  `brokapi_tbank::sandbox::open_sandbox_account`. С боевым адресом вызов отказывает до отправки. Имитация: `mock_tbank(new_sandbox=True)`. [Быстрый старт](python/quickstart.md#шаг-3-песочница-т-банка).
- **Финам без `FINAM_ACCOUNT_ID`.** Python, гейтвей и программа `brokapi` берут единственный счет секрета, а если их несколько, `Config` перечисляет номера:
  `FINAM_ACCOUNT_ID is not set and the secret sees 2 accounts: A12345, A67890`. Раньше номер был обязателен, а узнать его можно было только в кабинете.
  В Rust у `BrokerConfig::Finam` поле `account` теперь `Option<String>`.
- **Цена не на шаге отвергается и без `trading_params`.** Перед первой заявкой с ценой по инструменту клиент сам один раз читает его правила. Раньше проверка
  до отправки работала, только если бот перед этим вызвал `trading_params`, и цена не на шаге без него уходила брокеру. Касается `place` и `place_stop`
  у всех пяти брокеров. Не удалось прочитать правила - заявка уходит без проверки, шаг проверит брокер.
- **Средняя цена исполнения: где рецепт работает.** Сделки истории несут `cid` у Финама, АЛОР и Bybit, у БКС и Т-Банка нет. Книга говорила только про БКС.
  Для БКС и Т-Банка считайте по событиям `Execution`, они несут `cid`. Тест по всем пяти брокерам, [торговый бот](python/howto-trading-bot.md).
- **Бот с сигналом и стопом одним файлом:** рост цены за окно - покупка - стоп после исполнения - рестарт. Тест на имитации Финама. [Стоп-заявки, Python](python/stop-orders.md#бот-с-сигналом-и-стопом).
- **`brokapi cancel-all --help` предупреждает,** что снимутся и защитные стопы ботов, и чужие заявки на счете.
- **Книга: позиция на старте у каждой имитации** (SBER 10 или 30, у Bybit BTCUSDT 0.5), колонка в таблице [Тестов против имитаций](python/testing.md), с тестом.

## 0.1.0-alpha.7: потолки заявок, рычаги имитаций, Т-Банк без настройки сертификата, клиент на Go

- **Потолки заявок и режим только чтения.** `read_only`, `max_order_qty` и `max_order_value` в `brokapi.connect(...)`, в `[gateway.settings]` и в окружении
  (`BROKAPI_READ_ONLY`, `BROKAPI_MAX_ORDER_QTY`, `BROKAPI_MAX_ORDER_VALUE`). Проверка до отправки: отказ `Rejected` с кодом `read_only`, `max_order_qty` или
  `max_order_value`, квота и `cid` не тратятся. Из настройки и окружения действует более строгое, так код бота не снимет предел, который поставил человек.
  Гейтвей ставит свои потолки всем ботам, `brokapi check` их показывает. В Rust - `brokapi_client::OrderGuard` и `Client::start_with`. Страница
  [Потолки заявок и режим только чтения](guard.md). `mock.start_gateway(..., read_only=True)` поднимает такой гейтвей в тесте.
- **Рычаги Python-имитаций.** Сбои, которые бот обязан пережить, вызываются из теста на любом из пяти брокеров: `mock.set_price("SBER", "250")` двигает
  рынок (стакан вокруг цены, сделки и бары по ней, новое сообщение в открытые подписки), `mock.lose_order_answers()` теряет ответ на принятую заявку
  (`Unknown`), `mock.delay_orders(1)` с `request_timeout` дает поздний ответ, `mock.cut_streams()` рвет потоки счета (`Reconnected`), `brokapi.Limiter.from_toml`
  задает свои числа лимитов (`RateLimited` без брокера). Раньше рычаги были только в Rust. Таблица - в [Тестах против имитаций](python/testing.md#рычаги-имитации).
- **Исполнение в имитациях двигает счет.** Раньше позиции после `mock.fill` не менялись у всех пяти брокеров (Финам показывал `SBER` после покупки `GAZP`),
  история сделок Т-Банка была неподвижной, а Финам ставил `Filled` уже после первого частичного исполнения и считал `filled` по последнему, а не по сумме.
  Теперь позиция и поток портфеля идут за исполнениями, каждое исполнение - отдельная сделка истории. В Rust у Финама появился `server.state.fill(...)`.
- **Книга: закрыт ли бар.** Подписка на свечи присылает формирующийся бар несколько раз, в истории последний бар может быть незакрытым, а признака у `Candle`
  нет. В [Событиях](events.md#свеча-закрыта-или-еще-формируется) - правило и рецепт «только закрытые бары» с тестом.
- **`request_timeout` в настройках всех брокеров:** сколько вызов ждет ответа, в секундах, можно дробное. `brokapi.connect(..., request_timeout=5)` или `request_timeout = 5`
  в `[gateway.settings]`. Книга и раньше говорила, что таймаут задается в настройке клиента, но из Python и `brokapi.toml` его было не задать. Ноль, отрицательное число
  или текст дают `Config` с именем настройки.
- **Средняя цена исполнения.** В снимке заявки ее нет, рецепт по сделкам `executions` - в [торговом боте](python/howto-trading-bot.md). У `OrderState` поля `filled`
  и `left` заполнены только при частичном исполнении, это теперь сказано в описании: сколько исполнено в любом состоянии, лежит в `OrderSnapshot.filled`.
- **Т-Банк работает из Python и программы `brokapi` без настройки сертификата.** Оба адреса Т-Банка подписаны Russian Trusted Root CA, корнем Минцифры,
  которого нет среди общих корней, и первый запрос падал с `UnknownIssuer`. Теперь этот корень встроен и действует **только для адресов `tbank.ru`**: соединения
  с другими адресами и брокерами ему не доверяют. Отпечаток сверяется тестом на каждой сборке. Свой корень сверх встроенного: `TBANK_ROOT_CERT`, `root_certificate=`
  в `connect` или в `[gateway.settings]` ([Т-Банк](brokers/tbank.md#корневой-сертификат-минцифры)).
- **Клиент для ботов на Go.** Модуль `github.com/runinfra/brokapi/go` (каталог `go/`): клиент, сгенерированный из `.proto`, и подключение к гейтвею по его каталогу, с ключом,
  заголовками, ожиданием готовности и ошибкой библиотеки (`brokapi.Detail`). `protoc` не нужен: `go get github.com/runinfra/brokapi/go@v0.1.0-alpha.7`. Пример бота переживает перезапуск
  гейтвея и запускается тестом против имитации БКС: [Бот на Go](gateway/bots.md#бот-на-go). Работает с программой `brokapi` с версии 0.1.0-alpha.6.
- **После `Transport` на заявке тот же `cid` не уходит к брокеру.** Т-Банк и АЛОР перед первой заявкой по инструменту читают размер лота, Bybit читает правила символа.
  Если это чтение обрывалось, `place` и `place_stop` отвечали `Transport`, а повтор с тем же `cid` уходил к брокеру. Двойной заявки так не получалось, первая до брокера не дошла,
  но книга обещает другое: на `Transport` и `Unknown` повтора нет. Теперь `cid` после `Transport` израсходован, повтор дает `duplicate_place`, новую заявку ставьте с новым `cid`.
  Общая проверка `transport_uses_up_the_cid` идет для трех коннекторов.
- **БКС и АЛОР: `replace` с уже использованным новым `cid` больше не уходит к брокеру.** Ядро обещает для `replace` те же правила номера, что для `place`,
  но эти два коннектора новый `cid` не отмечали: повтор замены после `Unknown` уходил к брокеру, а на имитации АЛОР заявка переставлялась второй раз. Теперь повтор дает
  `duplicate_place`, как у Т-Банка. Общая проверка `replace_order` теперь проверяет и это.
- **Примеры ботов на Python узнают, чем кончилась заявка из `closed_offline`.** Торговый бот, бот гейтвея и пример инфраструктуры считали такую заявку законченной,
  не спросив брокера. Бот гейтвея называл ее отмененной. Если заявка исполнилась, пока бота не было, торговый бот покупал второй раз. Теперь они спрашивают `order_state`,
  журнал торгового бота помнит исполненное количество, а `Transport` на `place` бот разбирает как `Unknown`. Тесты: «исполнилась, пока бота не было» для всех трех.
- **Текст `Unknown` называет путь и для стоп-заявки:** `... ask the broker with order_state(cid) (a stop order: active_stop_orders())`. Раньше он отправлял
  только в `order_state`, а стоп-заявку тот не находит. Кто сравнивал текст целиком, сравнивайте класс ошибки.
- **Т-Банк: в `code` отказа номер брокера.** Раньше `code` был именем статуса gRPC (`InvalidArgument`), а номер ошибки T-Invest лежал только в `message`,
  и `30042` (не хватает активов) от `30014` (слишком длинный период свечей) отличался только текстом. Теперь `code` равен номеру: `"30042"`. Без номера остается имя
  статуса, `not_found` не изменился. **Что поменять:** сравнение `code == "InvalidArgument"` замените на номер. Частые номера - на странице [Т-Банк](brokers/tbank.md#ответы-брокера).

## 0.1.0-alpha.6: gRPC для других языков и обслуживание службы

- **Файлы `.proto` гейтвея собираются `protoc` и `buf`.** В 0.1.0-alpha.5 и раньше `protoc` отказывался от `gateway.proto`: вызовы `Portfolio`, `OrderBook`, `TradingParams`,
  `TradingStatus` и `Schedule` закрывали одноименные типы ответа (`"Portfolio" is not a message type`). Сборка на Rust этого не замечала. Теперь тип ответа у них записан полным именем,
  сообщения и номера полей не менялись, клиенты на Rust и Python пересобирать не нужно. Клиент на другом языке берите из этого выпуска или новее.
  Проверка `tools/proto-check` собирает файлы `protoc` и клиент на Go на каждой правке. В [Бот на другом языке](gateway/bots.md#бот-на-другом-языке) - команда генерации для Go.
- **Гейтвей больше не присылает событие заявки дважды** боту, который подписался на состояния заявок, стоп-заявок или сделки с `opts`. Гейтвей держит такую подписку сам,
  а подписка бота с `opts` открывала у брокера вторую. Боты на Rust и Python `opts` здесь не шлют и дубля не видели, клиент на Go или другом языке видел. Теперь `opts` у этих трех подписок не учитываются.
- **Bybit: `active_orders` и `active_stop_orders` тратят лимит чтений.** Раньше первая страница списка не тратила ничего, и частые опросы списка могли превысить лимит биржи
  (на демо-счете 60 одновременных вызовов прошли мимо счетчика). На странице [Bybit](brokers/bybit.md#лимиты) - сколько тратит каждый вызов.
- **Каталог состояния создается с правами 700** (`init`, `check`, `up` и каталог каждого гейтвея): в нем ключи доступа к службе и гейтвеям. Раньше он получал права 755.
  Уже существующий каталог свои права сохраняет, поправьте их сами: `chmod 700 <state_dir>`. `brokapi check` о таком каталоге предупреждает
  (`warning: the state directory ... can be read by other users`).
- **Книга: обслуживание службы.** В [Запуск и обслуживание](gateway/operations.md) - как обновить программу, копия и восстановление каталога состояния, мониторинг (`ps` отвечает 0 и при `failed`,
  проверка по `ps --json`), подключение по сети. В образце юнита systemd добавлены `KillMode=process` (без него systemd убивает гейтвеи вместе со службой), `StateDirectory` и `UMask`.
- **`brokapi ps --check`** выходит с кодом 1, если гейтвей не работает, и называет его: проверка для cron и мониторинга без разбора JSON. Сам `ps` по-прежнему отвечает 0.
- **`LAST ERROR` в `ps` и `status`** берет только строки `ERROR` и `WARN` журнала гейтвея (раньше, если их не было, в колонку попадала последняя строка любого уровня,
  например `INFO Restored 1 subscriptions`) и показывает, сколько времени назад это было: `3m05s ago: killed by signal 9`. В `ps --json` новое поле `last_error_age_s`.
- **Команда к гейтвею, который не отвечает, называет его состояние**: `is starting: try again in a few seconds`, `is stopped: start it with brokapi start ...`. Раньше в любом случае
  советовала запустить службу. Без службы такая команда теперь выходит с кодом 3 (службы нет), как `ps`, а не 4.
- **`brokapi --version` у сборки из git называет коммит**: `brokapi 1.2.0 (commit 1a2b3c4d5)`. Сборка из `main` и выпуск перед ней имели один номер, и их нельзя было
  различить. Готовые файлы из Releases тоже называют коммит тега, пакет с crates.io печатает номер, как раньше. То же значение в поле `version` у `Health` и `Info` службы.
- **Команда от пользователя, которому каталог состояния закрыт**, говорит `cannot read the state directory ...: it belongs to another user` и советует `sudo -u` (код 1).
  Раньше она отвечала `no service is running ... Start it with up` и под systemd подталкивала запустить вторую службу. `up -d` в такой каталог тоже отказывает. В `CallError`
  клиента службы новый вариант `NoAccess`.
- **Гейтвей, который не отвечает** (завис, остановлен `SIGSTOP`), в `ps` и `status` показывает `starting` и прочерки. Раньше рядом оставались последние цифры, как у работающего.
- **Образец юнита systemd: `StateDirectoryMode=0700`.** Без него systemd создает `/var/lib/brokapi` с правами 755, и каталог с ключами открыт всем пользователям машины
  (проверено временным юнитом). Еще в [Запуск и обслуживание](gateway/operations.md): создание пользователя и каталогов, команды `brokapi` через `sudo -u`, копия каталога
  в архив и обратно.
- **Книга: Go и другие языки.** Установка `protoc` и плагинов, какие файлы `.proto` брать (тег вашей версии), что делать, когда закончился поток `Events`, и что `opts`
  читает только `SubscribePortfolio`. Новое в книге помечается «с версии ...»: книга на сайте описывает `main` и опережает выпуск.
- **Книга: `RESTARTS`.** `start` и `restart` обнуляют счет к пределу `max_restarts`, а колонка `RESTARTS` считает все перезапуски с запуска службы. Раньше книга обещала
  обнуление колонки.
- **`brokapi check` предупреждает о двух гейтвеях на одном токене**: брокер видит одного клиента, а каждый гейтвей считает лимит сам. Правило и что делать - в [Конфиге](gateway/config.md#ведра-лимита).

## 0.1.0-alpha.4: Gateway, программа `brokapi`

- **Gateway: программа `brokapi`.** Одна программа из двух частей. Служба (`brokapi up`) держит связь со счетами БКС, Т-Банка, Финама и АЛОР за все ваши боты и
  отдает им gRPC, поэтому боты на любом языке делят один счетчик лимитов и не переподключаются к брокеру при каждом своем перезапуске. Команды управляют службой
  (`ps`, `top`, `start`, `stop`, `reload`), читают счет (`portfolio`, `book`, `quote` с ключом `--json`) и снимают заявки (`cancel-all`). Несколько служб с разными конфигами
  работают на одной машине. Для ботов на Rust есть клиент `RemoteClient`, для остальных языков - файлы `.proto` и [справочник](api-gateway.md).
  Страницы: [Gateway](gateway/index.md), [быстрый старт](gateway/quickstart.md), [Подключить бота](gateway/bots.md), [команды](gateway/commands.md).
- Программа ставится готовым файлом для Linux, macOS и Windows со [страницы выпусков](https://github.com/runinfra/brokapi/releases) или командой
  `cargo install brokapi-gateway --version 0.1.0-alpha.4 --locked` ([Установка](install.md#программа-brokapi-gateway)).
  Клиента для ботов на Go нет, подключение по `.proto` описано в [Подключить бота](gateway/bots.md#бот-на-другом-языке).
- **Python: подключение к гейтвею тем же `Client`.** `await brokapi.connect_gateway("bcs-main", bot="my-bot")` возвращает тот же `brokapi.Client`, что и `brokapi.connect`:
  бот переезжает с брокера на гейтвей заменой одной строки, а все его вызовы и `async for` по `client.events` остаются. Под `Client` тот же код на Rust, что у `RemoteClient`,
  поэтому события, пропуски и сверка работают так же. Потеря событий приходит событием `brokapi.Gap`, торговля после нее закрыта (`Degraded`) до `reconcile`, как после `Overflow`.
  Различия с прямым подключением: нет `client.limiter` (счетчик общий на гейтвей), `close()` закрывает только соединение бота. В `brokapi.testing` появились
  `mock.start_gateway()` и `gateway.restart()`. Страница: [Подключить бота](gateway/bots.md#бот-на-python).
- В гейтвее `Caps` теперь сообщает предел одного запроса истории свечей по таймфреймам (поле `candle_spans` в `.proto`), клиент режет по нему длинную историю на окна. Старые клиенты поле не читают, ничего не ломается.
- Rust: у `RemoteClient` появились `feed()` (поток событий, который сам переоткрывается и сообщает о потере как `FeedItem::Gap`), `close()`, `wait_ready()` и необязательная защита команд
  (`ConnectOptions::trading_gate`: `NotReconciled` и `Degraded` до сверки, как у коннектора, по умолчанию выключена). Крейт `brokapi-client` получил трейт `Account` и `call_by_name` для любого клиента счета.
- В книге больше нет отдельного раздела «CLI»: командная строка - часть Gateway. Старый адрес `cli/index.html` ведет на [Команды](gateway/commands.md).
- **Gateway на macOS: длинный путь до каталога состояния.** Гейтвей не стартовал, если путь до его сокета был длиннее 103 байт (`path must be shorter than SUN_LEN`), а в `~/Library/Application Support/...` или при длинном имени гейтвея это обычное дело. Теперь такой сокет лежит в личном коротком каталоге (права 700), а адрес берется из `gateway.addr` и `service.addr`. Тот же отказ на Linux был при пути длиннее 107 байт. Подробности: [Какие файлы где лежат](gateway/operations.md#какие-файлы-где-лежат).
- **Gateway на Windows: справка называет программу `brokapi`**, а не `brokapi.exe`, как на остальных системах.
- **Gateway на Windows: бот переподключался не к тому порту.** Гейтвей на Windows слушает свободный порт, и после перезапуска порт другой. Бот, подключенный по каталогу состояния (`connect_gateway` в Python, `RemoteClient::connect_dir` и `feed()` в Rust), шел по старому адресу и не получал ни событий, ни пропуска (`Gap`). Теперь адрес читается из `gateway.addr` при каждом переподключении, а ключ из `access.key` перечитывается, если гейтвей его отверг. На Linux и macOS адрес сокета не менялся, там это не проявлялось.
- **`brokapi status` и `top`: память `-` вместо `0 B`.** Пока служба не прочитала память нового процесса, команды печатали `0 B`. Теперь там `-`.
- **Т-Банк: стоп-заявка с потерянным ответом возвращается в списке с вашим `cid`.** Раньше после `Unknown` у `place_stop` стоп у брокера стоял, а
  `active_stop_orders` показывал его с `cid: None`, и код вида «нет стопа с моим `cid`, значит ставлю заново» ставил второй стоп. Теперь коннектор связывает стоп с `cid`,
  когда подходит ровно один (подробности: [Т-Банк](brokers/tbank.md#стоп-заявки)). Если подходящих стопов два, `cid` по-прежнему пуст.
- Что поменять у себя: после `Unknown` смотрите не только стоп с вашим `cid`, но и стопы без `cid` на той же бумаге и в ту же сторону: ваш мог оказаться среди них,
  второй не ставьте. Рецепт для всех брокеров: [Стоп-заявки, Python](python/stop-orders.md#потерянный-ответ). `protect_once` в примере теперь возвращает `Placement`, а не стоп или `None`.
- Python: `brokapi.testing` получил `mock.lose_stop_answers()`: брокер принимает стоп-заявки, а ответ теряется. Для проверки своего кода на этом сбое.

## 0.1.0-alpha.3: `subscribe_*` возвращается, когда поток открыт

- У БКС, Т-Банка и АЛОРа `subscribe_*` возвращается, когда поток открыт: заявку можно ставить сразу после подписки на статусы и исполнения.
  Если за `subscribe_ack_timeout` (3 секунды, у Т-Банка `request_timeout`) поток не открылся, придет `Transport`, подписку можно повторить.
  Что считается открытым потоком, по брокерам: [Круг событий](streams.md#подписка).
- У Финама по таймауту `subscribe_*` по-прежнему вернет `Ok`, поток дооткроется в фоне (`sub_status`).
- БКС: рыночная подписка, которую брокер отклонил, теперь возвращает `Rejected { subscription_refused }`, как у остальных.
- Что поменять у себя: ничего, если вы подписывались до заявки. В `UserDataConfig` и `MarketDataConfig` БКС появилось поле
  `subscribe_ack_timeout`. Если вы полагались на фоновое открытие при медленном АЛОРе, теперь придет `Transport`: повторите вызов.
