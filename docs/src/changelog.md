## 2026-10-22: АЛОР Брокер

Проверено на имитации и общим набором сценариев, вживую ничего не запускалось.

- **Новый брокер: АЛОР.** Флаг `alor` у крейта `brokapi` (`brokapi::alor`, нижний слой `brokapi::alor::protocol`), `brokapi.connect("alor")` в Python.
  Обычные заявки (лимитные и рыночные) с заменой лимитной, стоп-заявки и стоп-лимиты, свои сделки, портфель, стакан до 50 уровней, котировки,
  лента, свечи всех таймфреймов (10 минут есть у брокера), справочник. Страница: [АЛОР](brokers/alor.md).
- **Весь API брокера в клиенте.** Нижний слой `brokapi-alor-protocol` содержит метод на каждую операцию описания API (58 штук: справочник, рынок, портфель,
  заявки, стопы, группы заявок, оценка заявки, старые стоп-лосс и тейк-профит), подписки канала `/ws` и торговый канал `/cws`. Все, чего нет в общем
  интерфейсе, доступно через `raw()`. Таблица: [Покрытие API](coverage.md).
- **Как устроено.** Количество в штуках, как у всех: коннектор читает размер лота и переводит в лоты брокера. `cid` уходит комментарием заявки и
  заголовком `X-REQID`. Команды идут по HTTP и не повторяются. `subscribe_*` возвращается, когда брокер подтвердил подписку.
- **Что у АЛОРа иначе.** Нет расписания торгов (`schedule` отвечает `Unsupported`), нет справочника по ISIN, нет потока стоп-заявок. Рыночную
  заявку заменить нельзя. История своих сделок читается одним ответом до 1000 записей.
- **Имитация АЛОРа** в `brokapi-mocks` (`alor`) и `mock_alor()` в Python. Общий набор сценариев `brokapi-conformance` проходит, а для брокера
  без расписания в нем появился `market_data_history_without_schedule`.
- **Примеры.** АЛОР добавлен в программы `infrastructure` и `research` (Rust и Python), в `raw` (Python) и в живые пробы (`crates/alor/tests/live.rs`, только сборка).

## 2026-10-22, Python повторяет Rust: стоп-заявки, raw, запись событий

Проверено на имитациях, вживую ничего не запускалось.

- **Стоп-заявки в Python.** `place_stop`, `cancel_stop`, `active_stop_orders`, `subscribe_stop_orders` и типы `StopOrderKind`,
  `StopExpiry`, `StopOrderRef`, `StopOrderSnapshot`, `StopOrderState`. Правила те же, что у `place` и `cancel`: шлюз `reconcile`, `cid` от
  бота, повтор с тем же `cid` отвергается, `Unknown` не повторяется. Потока статусов стопов нет ни у кого из брокеров, метод дает
  `Unsupported`. Страница: [Стоп-заявки, Python](python/stop-orders.md).
- **`raw()` в Python.** `await client.raw("GetLastPrices", {...})`: имя метода и словарь, ответ словарем. У Т-Банка и Финама метод ищется по
  имени в вшитом описании `.proto`, у БКС по таблице имен из файла лимитов или как `"GET /путь"`. Квота берется по имени метода из общего
  счетчика, `command=True` для команд (потерянный ответ - `Unknown`, без повтора). Методы с потоком не отдаются (`Unsupported`). Страница:
  [Любой метод брокера, Python](python/raw.md).
- **Запись событий и проигрыш в Python.** Модуль `brokapi.record`: `EnvelopeWriter`, `EnvelopeReader`, `replay`, `ReplaySpeed`,
  `record_events` и ошибка `LogError`. Файл тот же, что у `brokapi_runtime::record`: журнал из Rust читается в Python и наоборот.
  Страница: [Запись событий и проигрыш, Python](python/record.md).
- **Для этого в протокольных крейтах Т-Банка и Финама добавлено:** `FILE_DESCRIPTOR_SET` (описание сервисов и сообщений API) и
  `TbankClient::grpc()` / `FinamApi::grpc()` (универсальный gRPC-клиент поверх того же канала и токена). Существующий код не меняется.
- **Имитация Т-Банка в Python:** `mock.fill` для стоп-заявки возвращает `ValueError` вместо паники (срабатывание стопа эта имитация не умеет).
  Срабатывание стопа проверено на имитациях БКС и Финама.
- **Python и Rust теперь совпадают по возможностям.** Отличие одно: `raw` в Python не отдает потоки и WebSocket-каналы БКС.

## 2026-10-21, вторая волна: безопасность, оставшиеся находки, публичный API, упаковка

Проверено на имитациях, вживую ничего не запускалось. Что **меняется** для тех, кто уже пишет код на библиотеке, помечено словом.

**Безопасность.**

- **Токены не попадают в `Debug` и в журнал.** `BcsConfig`, `TokenRequest` и `TokenResponse` печатают `<redacted>` вместо
  refresh-токена и токена доступа, настройки коннекторов БКС наследуют это. Из журнала БКС убраны целое сообщение заявки
  (`info!`) и сырой текст кадра, который не разобрался (`warn!`): остались вид ошибки, строка, столбец и размер. Заголовок
  JWT у Финама помечен как чувствительный.
- **БКС: команда не повторяется после 401.** **Меняется:** заявка, отмена и правка уходят один раз
  (`BcsHttpClient::post_command`). На 401 клиент обновляет токен для следующего вызова и возвращает 401 как ошибку
  (`Rejected` с кодом `http_401`), команду бот повторяет сам. Чтения повторяются, как раньше. Клиент теперь следит за сроком
  токена и обновляет его заранее (после 90% от `expires_in`), поэтому первая команда после суток работы не встречает 401.
- **`dotenv` заменен на `dotenvy`, `.env` ищется только в текущем каталоге.** **Меняется:** раньше файл искался и в
  родительских каталогах. Свой путь: `BcsConfig::from_env_file`, `TbankConfig::from_env_file`. В зависимостях пользователя
  `dotenv` меняется на `dotenvy`.
- **Адреса из переменных окружения только `https://`.** **Меняется:** `TBANK_ENDPOINT` и `FINAM_API_URL` с `http://` отвергаются
  (`TbankConfig::from_env` теперь возвращает `ProtocolError`, а не `VarError`). Адрес имитации задается в коде
  (`for_mock`, `with_endpoint`) или аргументом `endpoint` в Python.

**Корректность.**

- **БКС: лимиты по таблице брокера.** По 10 запросов в секунду на каждый сервис, 3 для истории операций, для заявок еще суточное
  ведро на 200000. Файлы лимитов теперь лежат в крейтах (`crates/*/limits.toml`), каталога `configs/` нет. В файле лимитов
  период можно писать в часах и днях (`"24h"`, `"1d"`), нулевой период и переполнение отвергаются.
- **Финам.** `UNAUTHENTICATED` на команде запускает обновление токена, команда не повторяется. У `Auth` и `TokenDetails` таймаут 10
  секунд. Срок токена это меньшее из `TokenDetails` и `exp - iat`. Стоп-заявки и SL/TP не попадают в поток обычных заявок. У
  исполнения чужой заявки `cid` остается `None`. `Resync` не обгоняет данные своей подписки, которые уже лежат в буфере.
  Теоретические позиции по активным заявкам брокер не отличает от открытых, об этом написано на странице Финама.
- **Т-Банк.** История исполнений запрашивает и маржинальные, и карточные сделки. Исполнение, пришедшее раньше ответа на заявку,
  получает `cid` задним числом. Отказ открыть поток (токен, право, лимит 80001) останавливает поток и возвращается ошибкой из
  `subscribe_*`, а не бесконечными попытками. Пауза переподключения сбрасывается после первого сообщения потока, не после
  открытия. Повторный `place_stop` не затирает запись, `cid` стопа не освобождается после отмены. HTTP/2 keep-alive идет раз в
  5 минут и только пока открыт вызов или поток. Свой корневой сертификат: `TbankConfig::with_root_certificate_pem`.
- **БКС.** Исправление (`executionType` 13) не создает новое исполнение. Ошибка подписки на рынок валит ту подписку, о которой
  она, а если по тексту не понять, все ожидающие. `cid` сообщения заявки это заявка, а не запрос, который сообщение вызвал.
  Не проверено вживую, в каком поле брокер что присылает.
- **Ядро.** `Conflate` держит последнее событие каждого вида (портфель, позиции, остатки у Т-Банка на одной подписке).
  Автомат заявки принимает настоящий порядок: исполнение раньше ответа на заявку, отмена раньше ответа. Позднее и повторное
  сообщение, согласное с известным, ничего не меняет, противоречие (отмена исполненной) пишется в журнал. Устаревший снимок не
  забирает исполненное назад. `place` у Т-Банка и Финама доходит до конца, даже если вызывающий бросил future. Заявки, которые
  не получили ответа, переводятся в `Unknown` по таймеру. Карты (`place_attempts`, реестр, `by_cid`, блокировки, книга
  стопов) хранят завершенные заявки сутки и не больше 100 000, **гарантия «один `cid` один раз» действует в этом окне**.
- **`Error::retryable_for_command()`.** **Меняется:** `Error::class()` это класс чтения. `Transport` там `Retryable`, и
  цикл повторов, который смотрит только на него, повторил бы команду. Для команд теперь `retryable_for_command()`: `true`
  только у `RateLimited`.

**Публичный API и упаковка.**

- **`#[non_exhaustive]`.** **Меняется:** на `Error`, `ErrorClass`, `Event`, `OrderState`, `ResyncReason`, `Backpressure`,
  `NativeId`, `ShutdownMode`, `StopOrderState` и на структурах `UserDataCaps`, `MarketDataCaps`, `StreamingCaps`,
  `OrderSnapshot`, `Envelope`, `ShutdownReport`, `ReconcileReport`. `match` по этим перечислениям нужна ветка `_`, структуры
  собираются конструкторами (`OrderSnapshot::new(...).with_price(...)`, `UserDataCaps::new(...)`), поля читаются как раньше.
  `OrderState` получил `cid()`, `name()` и `is_final()`.
- **Трейт `Connector`.** `caps()` и `shutdown` доступны через трейт, универсальный код может спросить возможности любого
  коннектора.
- **`in_flight_orders()`** у коннекторов Т-Банка и Финама: сколько команд отправлено и еще не получили ответ.
- **Упаковка.** `rust-version = "1.88"` (в книге было 1.85, `let`-цепочки требуют 1.88), у `tokio` включены только нужные
  возможности, у крейтов описание, репозиторий, адреса, ключевые слова и категории. Файлы лимитов лежат внутри крейтов, чтобы
  крейт собирался из опубликованного архива.

## 2026-10-21: исправления по разбору кода

Семь критичных находок независимого разбора, единообразие ошибок и новые проверки. Проверено только на имитациях, вживую ничего
не запускалось. Что **меняется** для тех, кто уже пишет код на библиотеке, помечено словом.

- **Количество везде в единицах инструмента, не в лотах.** `Qty` в заявке, стакане, сделке рынка, исполнении, позиции и
  объеме свечи значит одно и то же у всех трех брокеров: штуки, облигации, единицы валюты, контракты. Т-Банк считает лотами, его
  коннектор переводит в обе стороны (лот читается из справочника один раз, запрос `GetInstrumentBy`). **Меняется:** заявка к
  Т-Банку на 3 лота теперь `Qty::from(30)` при лоте 10, стакан, сделки и свечи Т-Банка приходят в штуках (в десять раз
  больше прежнего для лота 10), `TradingParams::min_qty` Т-Банка равен лоту, а не 1. Страница
  [Деньги, цены и количества](numbers.md#количество-единицы-инструмента-не-лоты) объясняет лот, единицу и размер контракта.
- **Количество не округляется.** **Меняется:** БКС раньше округлял `0.4` до 0 и `2.5` до 3 и отправлял. Теперь любое
  дробное, нулевое, отрицательное или не кратное лоту (если лот известен) количество это `Rejected` с кодом `invalid_qty` до
  отправки, `cid` остается свободным. Функция `whole_pieces` БКС стала строгой. Финам и БКС сверяют кратность лоту по
  `price_grid()` (`learn` теперь запоминает и лот).
- **Шлюз проверяется еще раз после очереди по бумаге.** Команда, которая стояла в очереди, когда шлюз закрылся (`Degraded`,
  остановка), больше не уходит к брокеру: она получает `Degraded` или `ShuttingDown`. Во всех трех коннекторах, для `place`,
  `cancel`, `replace` и стоп-команд.
- **БКС: статус 6 «Отменяется» не отмена.** **Меняется:** `cancel()` возвращает `Unknown`, а не `Ok`, пока брокер не прислал
  статус 4. В потоке и в ответах статус 6 приходит как `OrderState::Unknown` (не `Cancelled`), сверка считает такую заявку
  живой.
- **БКС: цена исполнения из потока.** Сообщения `orders/events/ws` несут итоги по заявке, а не числа одного исполнения. Цена
  теперь считается по приросту итогов между сообщениями одной заявки. Пример из документации раньше давал 489 вместо 244,5,
  позиция и прибыль считались неверно. **Меняется:** `map_ws_execution` принимает итоги предыдущего сообщения третьим
  аргументом.
- **История сделок постранично.** БКС читает все страницы по 100 записей (раньше первые 50), список БКС упирается в
  1000 последних сделок и тогда отвечает `Rejected { range_too_long }`. Финам читает остаток периода, пока ответ полный, и
  тоже отвечает `range_too_long`, если период не помещается. Раньше сделки пропадали молча.
- **Обрыв потоков заявок и исполнений виден боту.** Новое событие `Event::Reconnected { sub, gap_from }`: поток своих заявок
  или исполнений оборвался и открыт снова. Одновременно шлюз закрывается (`Degraded`) до `reconcile`. У всех трех брокеров.
  **Меняется:** `match` по `Event` без ветки `_` перестанет собираться, добавьте ветку. Описано в [Круге событий](streams.md#reconnected-поток-заявок-или-исполнений-оборвался)
  и в [Если что-то пошло не так](rust/recovery.md#поток-заявок-оборвался).
- **БКС: сверка решает по ответу `GET` по каждой заявке.** Живая заявка попадает в `confirmed`, закончившаяся или неизвестная
  брокеру в `closed_offline`, пустой или неясный ответ прерывает сверку. Раньше решал список заявок, где живая заявка могла
  не оказаться. Окно списка заканчивается на сутки позже локальных часов.
- **Ошибки одного вида.** **Меняется:** отказ токена у БКС и Финама теперь `Config` (у БКС был `Transport`, у Финама `Rejected`).

- **Общий набор проверок** (`brokapi-conformance`) получил сценарии: повтор `cid`, количество, чужой идентификатор,

## 2026-10-21: сверка с обновленной документацией Т-Банка и Финама

Проверено только на имитациях, вживую ничего не запускалось.

- **Т-Банк: `RESOURCE_EXHAUSTED` не всегда лимит запросов.** Раньше любой такой ответ был `RateLimited`. Теперь
  коннектор читает пятизначный номер ошибки брокера. Номера 80002, 80003, 80006 и неизвестные остаются `RateLimited`
  (для 80003 и 80006 без заголовка `x-ratelimit-reset` ждать предлагается 60 секунд, а не 1). Номер 80007 (максимум
  стоп-заявок по инструменту) стал `Rejected` с кодом `stop_orders_limit`, 80001, 80004, 80005 - `Rejected` с кодами
  `streams_limit`, `no_subscriptions`, `stream_lifetime`: повтор в этих случаях не поможет. **Меняется:** код, который
  повторял `place_stop` после `RateLimited`, на 80007 теперь получит `Rejected`.
- **Т-Банк: длинный список стоп-заявок.** Брокер отвечает ошибкой 30261, если стоп-заявок слишком много для одного
  ответа. `active_stop_orders` теперь на эту ошибку читает список по периодам (`from` и `to`), делит период пополам,
  пока каждая часть не поместится, и склеивает ответы. Не больше 40 запросов, дальше `Rejected` с кодом
  `stop_orders_response_limit`. Первый запрос по-прежнему без периода.
- **Финам: лот для торговли.** `trading_params` дополнительно спрашивает `GetAssetParams` (по первому счету токена).
  Если `trade_lot_size` больше нуля, он заменяет `lot_size` и `min_qty`. Ноль или отказ брокера на этот вызов оставляют лот
  из `GetAsset`. Это второй запрос справочника на вызов. Когда лоты различаются, неизвестно.
- **Финам: процент вместо штук в SL/TP.** Если у чужой SL/TP-заявки единица объема - процент от позиции, `qty` в
  `StopOrderSnapshot` теперь 0, а не процент. Раньше процент выдавался бы за штуки.
- **Финам: конец периода.** В описании Финама `interval.end_time` больше не необязательный. Запросы истории свечей и
  сделок и раньше всегда передавали оба конца, теперь это проверяет тест.

## 2026-10-20: ошибки переводятся в serde

- **Ошибки сериализуются.** `Error`, `ConfigError`, `TransportError` и `ErrorClass` переводятся в serde и обратно
  без потерь, как уже переводились события (`Envelope`, `Event`) и команды. Это нужно, чтобы ошибка и событие
  проходили через границу процесса (запись на диск, будущая служба) без изменений. Тест на круговой перевод
  проверяет цены с их знаками (`244.30` остается `"244.30"`), время в наносекундах и `cid`. `rx_mono` по-прежнему
  не сериализуется: это часы процесса-получателя.
- **Меняется:** у `Error::Unsupported` поле `capability` теперь `Cow<'static, str>` вместо `&'static str`. Сравнение
  со строкой (`capability == "stop_order_stream"`) работает как раньше. Если вы создаете эту ошибку сами, пишите
  `capability: "name".into()`.

## 2026-10-20: эталоны живого API, часы тестов, мелкие расхождения

Поведение, которое поменялось у тех, кто уже пишет код на библиотеке, отмечено словом **меняется**.

- **Эталоны живого API.** Живой прогон записывает ответы брокера в файлы (токены, номера счетов и заявок, ФИО чистятся до
  записи), а обычный тест без сети сверяет с ними имитацию: поля, типы, коды отказов. Пока эталонов нет, тест это
  сообщает и проходит. Как записать: [Живые прогоны](live.md#эталоны-как-записать-ответы-брокера). Живые тесты, которые перестали собираться
  после перехода на точные числа, исправлены, и `tools/check` теперь их собирает. Проверено только на имитациях,
  вживую ничего не записывалось.
- **Часы коннекторов.** Коннекторы берут время из `brokapi::runtime::now()`, то есть из часов `tokio`. Лимиты запросов,
  таймауты команд и паузы идут по тем же часам, что и тест, поэтому тесты не ждут по-настоящему: вместо `sleep` они ждут
  событие или сдвигают часы (`brokapi_mocks::time`). Подробности: [Тесты против имитаций](rust/mocks.md#время-в-тестах).
- **Мелкие расхождения, найденные при написании справочника, исправлены:**
  - `WsSession::subscribe` до первого подключения посылала команду дважды, теперь один раз. Сессия, которая так и не
    подключилась, после `drop` продолжала переподключаться, теперь останавливается сразу.
  - Т-Банк, `ping_interval` вне диапазона брокера: в запрос уходило значение, зажатое в диапазон, а порог тишины считался от
    значения как есть, и здоровый поток переоткрывался. Теперь оба считаются от зажатого значения (поток данных рынка 5 до 180 с,
    потоки счета 5 до 120 с).
  - **Меняется.** Т-Банк, `executions`: период, в котором больше 20 страниц по 1000 операций, дает `Rejected` с кодом
    `range_too_long`, а не молча обрезанный список.
  - **Меняется.** `unsubscribe` по номеру, которого нет: у всех трех брокеров `Rejected` с кодом `unknown_subscription`
    (у БКС и Финама было `Transport`). Сценарий в `brokapi-conformance`.
  - **Меняется.** `order_state` по неизвестному `cid` у БКС: `Rejected` с кодом `not_found` (было `Transport` с текстом
    `not found`), как у Т-Банка и Финама. Сценарий в `brokapi-conformance`.
  - **Меняется.** `TimeFrame` в `brokapi-bcs-protocol` совпадает со списком брокера: `M1 M5 M15 M30 H1 H4 D W MN`
    (убраны `M10`, `D1`, `W1`, а день и неделя называются `D` и `W`).
  - **Меняется.** У `ConnQuota` убрано поле `dedicated_command_conns`: ни один коннектор его не читал. Файлы лимитов с этим ключом
    читаются как раньше.
  - Справочник API (rustdoc) больше не подгружает собственные шрифты rustdoc.

## 2026-10-20: деньги, цены и количества - точные числа (ломающее изменение)

`f64` убран из публичного интерфейса там, где это деньги, цены, количества и лоты. Решение принято до публикации, чтобы
пользователям не пришлось ломать код после выхода. Страница: [Деньги, цены и количества](numbers.md).

- **Типы.** `Price`, `Qty` и новый `Money` хранят `Decimal` (крейт `rust_decimal`): `0.1 + 0.2 == 0.3`, `244.3` кратно `0.01`,
  `244.30` остается `244.30`. Создаются через `Price::new(dec!(250.15))`, `"250.15".parse()`, `Price::from(250)`,
  `Price::from_scaled(25015, 2)`. Из `f64` - только явный `from_f64_lossy`, он говорит в имени, что точность потеряна.
  В JSON число - строка.
- **Что стало точным:** `TradingParams` (`lot_size`, `min_qty`, `price_step`, `price_step_value`), `Balance`
  (`available`, `blocked`), `Execution::commission`, все цены и количества в заявках, стакане, сделках, свечах и стоп-заявках.
- **Округление до шага.** `Price::round_to_step(step, RoundMode::Down | Up | Nearest)`, `Qty::round_to_step`,
  `TradingParams::round_price` и `round_qty`. Точное, без шума двоичных дробей.
- **Проверка цены до отправки.** У каждого коннектора заявок есть `price_grid()`. Передайте шаг (`grid.learn(&params)`):
  `place`, `replace` и `place_stop` откажут ценой не на шаге кодом `price_off_step`, не потратив квоту и `cid`. Без шага проверки нет.
- **Форматы брокеров без потерь.** Т-Банк: `Quotation` и `MoneyValue` (`units` и `nano`) в `Decimal` и обратно, цена с больше
  чем девятью знаками - `invalid_price` до отправки. Финам: `google.type.Decimal` разбирается из строки, `Money` из `units` и
  `nanos`. БКС: числа JSON читаются в `Decimal` из текста (`serde_json` с `arbitrary_precision`), `244.30` и `0.0001` не теряют вид.
  Проценты и доли в моделях БКС (21 поле) остались `f64`.
- **Что поменять в своем коде:** таблица на странице [Деньги, цены и количества](numbers.md). Коротко: `Price::new(250.0)` ->
  `Price::new(dec!(250))` или `Price::from(250)`, `.value()` -> `.decimal()`, `f64_to_quotation` -> `decimal_to_quotation`, цены в
  `bcs-protocol` и `utils::precision` - `Decimal`, в конфигах `UserDataConfig` новое поле `price_grid`.
- **Проверка.** Случайные числа туда и обратно на всех трех форматах, примеры, где `f64` расходится с сеткой (`244.3 % 0.01`,
  `101.05 / 0.05`), проверка шага у каждого коннектора. Примеры книги и справочник переписаны под новые типы: 925 тестов и 488 примеров справочника зеленые (`tools/check`). Что брокеры вживую шлют
  числа именно так, как в документации, не проверено вживую.

- **Новые страницы:** [Ошибки и что с ними делать](errors.md) (по образцу Stripe), [Запуск, рестарт и остановка](rust/lifecycle.md),
  [Если что-то пошло не так](rust/recovery.md), [Лимиты запросов](limits.md), [События и возможности](events.md). Таблицы
  и порядок действий вынесены из объяснений.
- **Сообщения ошибок** `Unknown`, `NotReconciled`, `Degraded`, `ShuttingDown` теперь говорят, что делать, и совпадают с
  текстом на странице ошибок (тест `tests/docs_errors.rs`). `Rejected` печатается как `rejected: код: текст`.
- **Сверка книги с кодом.** Порядок проверок в `place`: шлюз, вход, квота, очередь по бумаге, и только потом `cid`
  помечается использованным (в схеме раньше стояло наоборот). Отмена тратит свое ведро и общее `global`.
- **Вид книги:** своя тема (с 2026-10-21 в стиле brokapi, см. выше). Шрифты лежат в книге, внешних запросов нет.
- **Схемы** рисуются из локальных файлов (`mdbook-mermaid`), без запросов к CDN.
- **Примеры** книги лежат в `examples/` корня и запускаются тестом `tests/examples.rs` против имитации.

## 2026-10-19, ночь: справочник API и примеры, которые запускаются

- **Справочник по каждому методу, типу, полю и ошибке** собран из кода (rustdoc, на английском) и лежит рядом с книгой:
  [Справочник API](api.md). У всех десяти крейтов библиотеки описано каждое публичное: что делает, какие ошибки возвращает,
  что не проверено на настоящем API.
- **Каждый пример - тест.** 473 примера в справочнике запускаются против имитации брокера, без сети и денег. Программы из
  `examples/` у трех коннекторов тоже идут против имитации. Настоящий брокер включается переменной `GATEWAYS_LIVE=1`
  (только чтение). Сломался пример - не проходит проверка `tools/check`.
- **Имитации брокеров** вынесены в отдельный крейт `broker-mocks`. Он нужен тестам и примерам и не входит в обещания библиотеки.
- **Исправлено при документировании:**
  - `BrokerLimiter` терял квоту, если маршрут метода указывал на несуществующую корзину.
  - БКС: поля прибыли и убытка портфеля (`unrealizedPL` и другие) читались с неверным регистром и оставались пустыми.
  - БКС: котировки в потоке читали только старые названия полей `ask` и `lastPrice`, документация брокера шлет `offer` и `last`.
    Теперь читаются оба.
  - БКС: слишком длинный ответ с русским текстом, который не разобрался как JSON, вызывал панику вместо ошибки.
  - БКС: сделка с неизвестной стороной больше не получает сторону наугад (поток давал покупку, история - продажу), такая
    запись отбрасывается.

## 2026-10-19, вечер: БКС выровнен с Т-Банком и Финамом

Документацию сверили с кодом и нашли места, где БКС вел себя иначе, чем остальные и чем требует спецификация. Исправлено:
- **`Overflow` и `Degraded`.** Полный буфер `Lossless`-подписки у БКС теперь дает `Event::Overflow`, торговые команды
  возвращают `Degraded` до `reconcile`. Раньше пакет молча отбрасывался с записью в лог. Буферы подписок вынесены в
  `broker-runtime` (`Emitter`) и общие у Т-Банка и БКС.
- **`Resync`.** После переподключения WebSocket БКС присылает `Resync { SubscriptionReset }` по каждой подписке на стакан,
  раньше новых снимков. Раньше событие не выдавалось нигде.
- **`cid` и квота.** Порядок один у всех трех: шлюз, проверка входа, квота, и только потом `cid` помечается использованным.
  После `RateLimited` (и ошибки входа) тот же `cid` годен. У БКС было наоборот. Правило в [Заявках](orders.md) переписано,
  тесты есть у всех трех брокеров.
- **`find(ByKind)`** у БКС читает все страницы списка (по 100), а не первые 50.
- **`default_limits()`** у БКС, как у двух других. Пример и [Быстрый старт](rust/quickstart.md) не читают файл с диска.
- **Пауза переподключения** выровнена: 0,5 с, удвоение до 30 с у всех трех (было 1-60, 0,2-10 и 0,5-30). У БКС границы в
  настройке коннектора (`reconnect_min`, `reconnect_max`), пауза возвращается к минимуму только после 10 секунд жизни
  соединения.
- Внутренняя памятка заменена отсылкой на эту документацию.
Живыми прогонами это не проверено, новые вопросы к БКС добавлены в [Живые прогоны](live.md).

## 2026-10-19

**Документация.** Добавлена эта документация.

**БКС переведен на актуальные методы.**
- Постановка, отмена и изменение заявки идут синхронными методами (`/orders/sync`, `/orders/cancel/sync`,
  `/orders/edit/sync`): ответ брокера известен сразу, отказ внутри ответа 200 тоже становится `Rejected`, в `OrderAck`
  попадает настоящий номер брокера.
- Статус заявки - `GET /orders`, список - `POST /orders/search`, статусы и исполнения - один канал `orders/events/ws`.
  Прежние формы запросов коннектор не вызывает (имитация отвечает на них 404, тест считает обращения).
- Стоп-заявки БКС добавлены как условные заявки. Срок, направление срабатывания и смысл поля `price` документация не
  описывает, выбраны безопасные толкования (подробно в [Стоп-заявках](rust/stop-orders.md)).
- Имитация БКС переписана по схемам с сайта брокера. Сверка нашла и исправила ошибки: статусы списка заявок были
  угаданы, список не несет `clientOrderId`, `reconcile` не мог подтвердить ни одной заявки, `replace` без количества
  ставил 1, история своих сделок ждала не ту обертку, ответ HTTP 4xx на команде считался ошибкой связи, а не отказом,
  лента сделок и таймфреймы `D` и `W` шли в неверном виде.

**Полный API и `raw()`.**
- В клиентах трех брокеров есть все методы их API.
- У каждого коннектора (MD и UD) появился `raw()` для вызова любого метода с общим счетчиком лимитов
  ([raw](rust/raw.md)). Метод без маршрута тратит общее ведро, бесплатных вызовов нет.
- Стоп-заявки стали общей возможностью (`StopOrderExecutor`) у всех трех брокеров.
- Таблица [Покрытие API](coverage.md) собирается скриптом по коду, методов «нет» не осталось.

**Доводка трех коннекторов до «написан и проверен на имитации».**
- Порядок команд по бумаге (`InstrumentLocks`): блокировка по очереди, ключ - `symbol@mic`, снимается при любом
  исходе.
- Т-Банк: справочник по виду (`find(ByKind)`), свое ведро лимитов для тяжелых списков.
- БКС: поток исполнений. Найдено и исправлено: вторая подписка UD затирала первую.
- Финам: свечи 10 минут собираются из 5-минуток. `replace` остался `Unsupported`.
- Лимиты загружаются общей функцией для любого брокера.

**Т-Банк и Финам.**
- Т-Банк: `tbank-protocol` (gRPC по официальным `.proto`) и `broker-tbank`. Несколько счетов: UD на счет, один счетчик
  лимитов на пользователя.
- Финам: `finam-protocol` с менеджером токенов, который обновляет JWT заранее, и `broker-finam`.

**Общие сценарии (`broker-conformance`).** Одни и те же сценарии идут против имитации каждого брокера. Сразу нашли
ошибки БКС, все исправлены:
- подписки MD шли в обход ядра: события без `sub`, не работали режимы буфера.
- `reconcile` терял `cid`, которого брокер не знает: теперь такие номера попадают в `closed_offline`.
- заявка, упавшая по ошибке, оставляла бумагу занятой в очереди команд до перезапуска: очередь заменена на
  блокировку, которая снимается при любом исходе.
