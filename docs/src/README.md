# Что это

**brokapi** - единый интерфейс к торговым API. Один и тот же код бота работает с любым брокером. Начинаем с API
брокеров российского рынка: **БКС**, **Т-Банк** и **Финам**. Дальше другие брокеры и биржевые протоколы под тот же
интерфейс.

Для ИИ-агентов: [llms.txt](llms.txt) / [llms-full.txt](llms-full.txt). Для тех, что пишут на Python: [python/llms.txt](python/llms.txt)

**Стадия: закрытая альфа.** Проверено только на имитациях, вживую нет, интерфейс до беты может меняться.
Что проверено и что нет: [Готовность](readiness.md).

## Что общее у всех путей

- **Переводчик.** Бот говорит на одном языке (заявка, стакан, событие) со всеми тремя брокерами. Разница протоколов
  (REST, WebSocket, gRPC) спрятана внутри. Сменить брокера - поменять коннектор, код бота почти не меняется.
- **Предохранитель.** Главная задача библиотеки - чтобы бот никогда не поставил заявку дважды и не торговал вслепую.
  Поэтому команда без ответа не повторяется, а торговля закрывается, когда данные о своих заявках могли потеряться.
- **Без памяти.** Между запусками библиотека ничего не хранит. Журнал заявок ведет бот, библиотека дает номер `cid` в
  каждом событии заявки и сверку со счетом.

Книга устроена так. **Как устроено** - карта и три круга механики, с причинами: почему сделано так и что будет
иначе. **Брокеры** - особенности БКС, Т-Банка и Финама. Дальше разделы продуктов: у каждого свой быстрый старт и
свои инструкции. **Справочник** - ошибки, события, контракт для агентов, покрытие API и справочник из кода. **Состояние** -
что проверено, что нет и что менялось. Код на общих страницах дан вкладками Rust и Python там, где он есть.

Все утверждения сверены с кодом. Где проверить нечем, это сказано прямо.

## Что умеет

| Возможность | Что внутри |
|---|---|
| Рыночные данные | стакан (снимок и поток), сделки рынка, котировки, свечи, справочник инструментов, лот и шаг цены, статус торгов, расписание |
| Заявки | постановка, отмена, изменение (где оно есть у брокера), статус по номеру бота, список активных, поток статусов |
| Свои сделки | история и поток исполнений |
| Портфель | снимок и поток: деньги и позиции |
| Стоп-заявки | стоп-лосс, тейк-профит, стоп-лимит одним набором методов |
| Сверка после рестарта | бот приносит список своих заявок, библиотека сравнивает его с брокером |
| Лимиты запросов | общий счетчик на область, где брокер считает лимит |
| Любой другой метод брокера | через `raw()`, с теми же токеном, адресом и счетчиком лимитов |

## Из чего состоит

У каждого брокера два коннектора: **MD** (рыночные данные, один на брокера) и **UD** (заявки, свои сделки, портфель,
один на счет). Как они связаны с ботом, с лимитами и между собой, показывает [Карта](architecture.md).

Общие трейты (`OrderBookSource`, `OrderExecutor`, `StopOrderExecutor` и другие) закрывают то, что умеют все три
брокера. Бот, написанный на них, работает с любым брокером. Все остальное, что есть у брокера (купоны, отчеты,
избранное, новые методы), доступно через метод `raw()` каждого коннектора: [raw](rust/raw.md). Сколько методов брокера
закрыто общим интерфейсом, а сколько только `raw()`: [Покрытие API](coverage.md).

## Три правила, на которых все держится

1. **`cid` придумывает бот** и записывает у себя до отправки. Это единственная нить, по которой можно спросить
   брокера о заявке без ответа. Если номер выдает библиотека, он теряется вместе с ответом, и после падения бот не
   знает, что за заявка могла встать. Подробно: [Круг команд](orders.md).
2. **Команда без ответа не повторяется.** `Unknown` выясняется у брокера, новая попытка идет с новым `cid`. Заявка без
   ответа могла встать, и повтор дал бы две заявки на счете. Что делать вместо повтора: [Если что-то пошло не так](rust/recovery.md).
3. **Торговля только после сверки.** После старта, после перегрузки, при сомнении. Пока бот не знает, какие заявки уже
   стоят у брокера, новая команда может задвоить заявку или спорить с той, которую бот не видит. Подробно:
   [Круг жизни](reconcile.md).

## Чего библиотека не делает

- **Не придумывает номер заявки.** `cid` создает бот, по нему он узнает свою заявку после рестарта.
- **Не повторяет команды.** Заявка, на которую не пришел ответ, не отправляется второй раз. Ни при каких условиях.
- **Не хранит состояние на диске.** Журнал своих заявок ведет бот.
- **Не собирает общий портфель по счетам и не выбирает счет для заявки.** Это слой над коннекторами.
- **Не трогает чужие заявки.** Заявки, поставленные руками или другим роботом, она только показывает.
- **Не снимает заявки при остановке.** Заявка на бирже переживает процесс бота.

## Честный статус

| Что | Состояние |
|---|---|
| Код трех брокеров: MD, UD, стоп-заявки, `raw()` | написан |
| Проверка на имитации брокера (mock-серверы) и общим набором сценариев `brokapi-conformance` | есть, таблица в [Готовности](readiness.md) |
| **Проверка на настоящем API через коннекторы** | **не было ни у одного брокера** |
| Проверка нижнего слоя БКС (`brokapi-bcs-protocol`) на настоящем API | была: авторизация, справочник, свечи, потоки, портфель, создание, статус и отмена заявки по прежним методам |
| Актуальные методы заявок БКС, поток `orders/events/ws`, условные заявки БКС | вживую не пробовались |

Имитация проверяет, что библиотека правильно разбирает то, что брокер описал в документации. Она не
доказывает, что настоящий брокер отвечает именно так. Поэтому в разделе [Живые прогоны](live.md) собраны
вопросы, на которые ответит только настоящий счет. Пока они открыты, **не запускайте библиотеку с настоящими
деньгами без собственной проверки**: сначала песочница Т-Банка, затем заявки далеко от рынка и минимальным объемом.

Библиотека на стадии закрытой альфы. Интерфейс может меняться до беты.
