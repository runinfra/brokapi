# Как скачать историю свечей

Инструкция. Цель: выгрузить длинную историю свечей по нескольким бумагам в файлы, не нарушая лимитов брокера, и после сбоя
продолжить с того места, где остановились. Код - куски программы `history.py`, она запускается тестом против имитации БКС.

## Как библиотека читает длинную историю

Один запрос свечей брокер принимает лишь в пределах: у БКС не больше 1440 баров, у Т-Банка предел зависит от таймфрейма, у Bybit не больше 1000 баров, у Финама
он осторожный, АЛОР предела не называет (вся история одним запросом, если не задать окно). Год часовых баров поэтому не один запрос, а несколько, и каждый тратит квоту. `candle_pages` режет период на окна
по пределу брокера и читает их по одному на каждом шаге `async for`:

- на `RateLimited` ждет `retry_after` и читает окно снова
- на `Transport` читает окно еще раз с растущей паузой (чтение безопасно повторять, команды нет)
- на любой другой отказ останавливается: тот же запрос даст то же
- склеивает окна без дублей: бар, который вернули оба соседних окна, остается один раз
- страница бывает пустой (выходные, торги стояли). Это не конец, конец - `StopAsyncIteration`

```python
async for page in client.candle_pages(instrument, brokapi.Timeframe.H1, start, end):
    ...  # page: список Candle, по порядку времени
```

Простой `client.candles(...)` читает один запрос, и если период длиннее предела, это `Rejected`. Для нескольких тысяч баров есть
`load_candles`, он собирает все в память одним вызовом, а для больше пишите по страницам.

## Файл сам себе контрольная точка

Один файл на бумагу: текст, строка на бар (`время, открытие, максимум, минимум, закрытие, объем`). Продолжение идет с конца файла:
отдельного состояния нет, поэтому оно не может разойтись с данными. Сбой посреди записи оставляет оборванную строку, ее отрезают
перед продолжением, иначе следующая страница приклеится к ней.

## Выгрузка

```python
{{#include ../../../crates/python/examples/history.py:download}}
```

Ошибки разбираются по классу (`error.error_class`):

| Класс | Примеры | Что делает выгрузка |
|---|---|---|
| `RETRYABLE` | `RateLimited` после всех ожиданий, `Transport` после повторов | ждет и продолжает с конца файла, до пяти попыток подряд без продвижения |
| `FATAL` | `Rejected`, `Config`, `Unsupported` | та же ошибка повторится: поднимается наверх, надо проверить бумагу, таймфрейм и период |

Любое чтение тратит квоту, не только свечи: `instrument` у Т-Банка, `last_trades`, подписка. Любое может вернуть `RateLimited`.
Если выгружаете несколько бумаг, делайте это по очереди на один клиент: у брокера один счетчик лимитов на все.

## Как проверить

Для этой команды нужен клон репозитория (`git clone https://github.com/runinfra/brokapi`, затем `pip install brokapi pytest pytest-asyncio`): тесты и примеры в пакет `pip install brokapi` не входят.

```bash
cd crates/python
pytest tests/test_examples.py -k history
```

Тест выгружает 100 дней часовых баров (2400 штук, БКС отдает 1440 за запрос), проверяет, что баров ровно 2400 без пропусков и
дублей, что второй запуск ничего не просит у брокера, и что после обрезанного файла с битой строкой выгрузка дописывает ровно
недостающее. Пределы брокеров взяты из их документации.
