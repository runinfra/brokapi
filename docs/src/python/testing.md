# Как тестировать код против имитаций брокеров (Python)

Инструкция. Цель: проверить своего бота без брокера, сети и денег. В пакете есть модуль `brokapi.testing` с имитациями
брокеров. Каждый пример этой книги идет именно на них.

Имитацию можно запустить и обычным скриптом через `asyncio.run`, не только тестом: так начинается [Быстрый старт](quickstart.md#шаг-2-первая-программа-без-токена-и-без-денег).

## Что такое имитация

Это настоящий сервер на `127.0.0.1` со случайным портом, который говорит на протоколе брокера: HTTP и WebSocket у БКС, АЛОРа и Bybit, gRPC у
Т-Банка и Финама. Клиент `brokapi.Client` подключается к нему так же, как к брокеру, поэтому тест идет по тому же коду, что и боевой
запуск, а не по подмене. Сервер хранит состояние: поставленные заявки видны в `active_orders`, снимаются, исполняются.

**Чего имитация не доказывает:** что настоящий брокер отвечает так же. Имитации написаны по документации брокеров.

## Минимальный тест

```python
import brokapi
from brokapi.testing import mock_bcs


async def test_the_bot_reads_a_book():
    async with await mock_bcs() as mock:       # сервер стартовал
        client = await mock.connect()          # клиент к нему подключен
        sber = await client.instrument("SBER")
        book = await client.order_book(sber, depth=5)
        assert book.bids[0].price < book.asks[0].price
    # блок кончился: клиенты закрыты, сервер остановлен
```

Тесты асинхронные. Подойдет `pytest-asyncio` (`asyncio_mode = "auto"`) или `anyio`, в самом пакете тесты на первом.

| Функция | Что поднимает | Счета | Позиция на старте |
|---|---|---|---|
| `mock_bcs()` | БКС | один, токен на запись | SBER 10 |
| `mock_tbank()` | Т-Банк | два: `acc-a` (по умолчанию) и `acc-b` | SBER 30 на `acc-a` |
| `mock_finam()` | Финам | два: `ACC1` (по умолчанию) и `ACC2` | SBER 10 на `ACC1` |
| `mock_alor()` | АЛОР | один портфель `D00001` (`synthetic_candles` не нужен: ряд всегда под заданный период) | SBER 30 |
| `mock_bybit()` | Bybit | один счет, тестовый контракт `MOCKUSDT` (шаг количества и самое малое количество 10, шаг цены 0.01), еще есть `BTCUSDT`. `synthetic_candles` не нужен: ряд всегда под заданный период | BTCUSDT 0.5 |

Позиция на старте есть у каждой имитации: так тест портфеля и сверки видит непустой счет. Бот, который ищет «позицию без стопа», найдет и ее:
фильтруйте позиции по своим инструментам. Задать свою стартовую позицию пока нельзя, ее двигают только исполнения (`mock.fill`).

У всех есть `synthetic_candles=True`: `candles` тогда отвечает рядом под заданный период, по бару на шаг таймфрейма, и отвергает
период длиннее предела брокера, как настоящий. Выключено, отвечает тремя фиксированными барами.

`mock.connect(**kw)` принимает те же аргументы, что `brokapi.connect`: `name`, `limiter`, `account_id` и другие. Так делают два
клиента на один счет или второй счет, как в [инфраструктуре](howto-infrastructure.md).

## Исполнить заявку

Статусы и исполнения приходят событиями. Чтобы проверить, что бот делает при исполнении, имитацию просят исполнить заявку:

```python
mock.fill(cid, qty=params.min_qty, price=Decimal("100.00"))
```

У БКС, Финама, АЛОРа и Bybit нужны `qty` и `price`: `qty` - объем этого исполнения, меньше объема заявки дает частичное исполнение, следующий
вызов добавляет к нему. Т-Банк исполняет заявку целиком по ее цене и эти аргументы не читает. Т-Банку и Финаму можно указать `account`.

Исполнение двигает счет, как у брокера: позиция по инструменту растет на покупке и падает на продаже (`positions`, `portfolio` и поток
`subscribe_portfolio`), а каждое исполнение - отдельная сделка в `executions` со своим `trade_id`. Деньги после исполнения не меняются: баланс
остается тем, что записан в имитации.

## Рычаги имитации

Бот обязан пережить сбои, которых на песочнице не дождаться: потерянный ответ, обрыв, отказ по лимиту. Имитация вызывает каждый из них по
команде теста, на любом из пяти брокеров одинаково.

| Что проверить | Рычаг | Что увидит бот |
|---|---|---|
| Цена дошла до уровня бота | `mock.set_price("SBER", "250")` | стакан вокруг цены: лучшая покупка на 0.01 ниже, продажа на 0.01 выше, дальше по шагу. Сделки и бары по этой цене. Каждая открытая подписка на тикер (стакан, котировка, сделки, бары) получает новое сообщение |
| Заявка исполнилась | `mock.fill(cid, qty=..., price=...)` | события заявки и исполнения, позиция и история сделок сдвинулись |
| Брокер принял заявку, ответ потерян | `mock.lose_order_answers()`, вернуть `mock.lose_order_answers(False)` | `place` кончается `Unknown`, заявка у брокера. Повтор с тем же `cid` получает `Rejected` с кодом `duplicate_place`, в сеть он не уходит |
| То же со стоп-заявкой | `mock.lose_stop_answers()` | `place_stop` кончается `Unknown`, стоп у брокера (`active_stop_orders()`) |
| Брокер отвечает поздно | `mock.delay_orders(1)` и `mock.connect(request_timeout=0.2)` | через 0.2 секунды `Unknown`, а событие заявки приходит, когда задержка кончилась. Пауза настоящая, держите ее короткой. У БКС, АЛОРа и Bybit задержка держит и отмену с заменой |
| Обрыв связи со счетом | `mock.cut_streams()` | `Reconnected` по потокам заявок и исполнений, торговля закрыта (`Degraded`) до нового `reconcile`. Потоки рынка не рвутся |
| Отказ по лимиту запросов | `mock.connect(limiter=brokapi.Limiter.from_toml("bcs", текст))` | `RateLimited` с `retry_after` раньше, чем запрос ушел. Текст - раздел `[bcs]` файла лимитов, формат в [Лимитах запросов](../limits.md#свои-числа-формат-файла). Малый бюджет: `burst = 1` и долгий `per` |
| Гейтвей упал | `gateway.restart()` | `Gap` с причиной `new_epoch` ([ниже](#гейтвей-в-тесте)) |

Без `set_price` у имитации свои записанные цены, и они не согласованы между собой: стакан Т-Банка около 274, а бары около 270. Нужна согласованная
картина - задайте цену. `ticker` - тикер брокера (`"SBER"`, `"GAZP"`, у Bybit `"MOCKUSDT"`), класс не нужен.

## Ждать события, а не время

В тестах нет `sleep`. Ждите событие или ответ, а время не отсчитывайте: пауза либо лишняя, либо коротка.

```python
async def wait_event(client, kind, **match):
    async for envelope in client.events:
        if isinstance(envelope.payload, kind) and all(
            getattr(envelope.payload, k) == v for k, v in match.items()
        ):
            return envelope
```

Оберните чтение в `asyncio.wait_for(..., 10)`: предел нужен, чтобы тест, у которого событие не пришло, упал, а не повис. Порядок
событий у разных брокеров разный: в имитациях БКС и Финама сначала приходит событие заявки, а у Т-Банка исполнение пришло раньше статуса
`Filled`. Не рассчитывайте на порядок между двумя видами событий, собирайте их, пока не набрались оба.

## Гейтвей в тесте

Бот, который работает через [гейтвей](../gateway/index.md), тоже проверяется без брокера и сети. `mock.start_gateway()` поднимает в вашем процессе настоящий гейтвей на имитации,
а `gateway.connect(bot="my-bot")` дает клиента, которого делает и `brokapi.connect_gateway`:

```python
async def test_the_bot_behind_a_gateway():
    async with await mock_bcs() as mock:
        gateway = await mock.start_gateway("bcs-main")
        client = await gateway.connect(bot="my-bot")      # тот же Client, что у mock.connect()
        ...
        await gateway.restart()   # гейтвей умер, на его месте новый процесс: бот получит brokapi.Gap
```

`restart()` - тот сбой, который бот за гейтвеем обязан пережить. Клиенты остаются подключены, находят новый процесс, и в их потоке появляется `Gap` с причиной `new_epoch`.
Заявки, стоящие у имитации, никуда не деваются: новый гейтвей сверяет с ними свой журнал до первой команды. Гейтвей останавливается вместе с имитацией. Пример с перезапуском:
[Подключить бота](../gateway/bots.md#бот-на-python).

## Как устроены тесты самого пакета

В `crates/python/tests/`: чтение и заявки на каждом брокере (`test_brokers.py`), общие правила (`test_bcs.py`), общие счетчики лимитов,
слияние потоков и история (`test_infrastructure.py`), точные числа и ошибки (`test_codec.py`, `test_errors.py`, `test_numbers.py`),
примеры книги (`test_examples.py`, `test_rules.py`, `test_guides.py`), рычаги имитаций (`test_mocks.py`). Тесты лежат в клоне репозитория (`git clone https://github.com/runinfra/brokapi`), в пакет `pip install brokapi` они не входят. Запуск:

```bash
cd crates/python
maturin develop        # собрать расширение в текущее окружение (нужен Rust)
pytest tests
```

Rust не нужен, если поставить из PyPI пакет той же версии, что у клона: `pip install brokapi pytest pytest-asyncio`, и сразу `pytest tests`.
