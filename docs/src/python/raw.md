# Любой метод брокера, Python

Инструкция. Общий интерфейс закрывает то, что умеют все брокеры. Но у каждого брокера есть много своего: купоны и дивиденды, отчеты,
избранное, корпоративные действия, свежие методы. Чтобы они не оказались закрыты, у клиента есть `await client.raw(...)`. Он вызывает
**любой метод API брокера** с теми же токеном, адресом и счетчиком лимитов, что у самого клиента. Общая часть, одна для Rust и Python:
[Любой метод брокера: raw](../rust/raw.md). Там примеры на Rust и правила квоты. Здесь то, как это выглядит в Python. Код ниже - куски
программы `raw.py`, она запускается тестом против имитаций.

```python
reply = await client.raw(method, args=None, *, command=False)   # reply: dict (или list, как ответит брокер)
```

В Rust метод вызывается замыканием над типизированным клиентом. В Python замыкания нет, поэтому метод называют строкой, а аргументы
передают словарем. Ответ приходит словарем.

## Как называть метод и что передавать

| Брокер | `method` | `args` |
|---|---|---|
| Т-Банк | имя метода из описания API: `"GetLastPrices"`, `"GetUserTariff"`. Если у двух сервисов одно имя, `"UsersService/GetAccounts"` | сообщение запроса словарем, имена полей как в `.proto` (snake_case, camelCase тоже принимается) |
| Финам | то же: `"LastQuote"`, `"Clock"` | то же |
| БКС | имя из файла лимитов: `"GetQuotes"`, `"GetPortfolio"`, `"GetOperationHistory"`, или `"GET /путь"`, `"POST /путь"` для любого другого метода | `query` (параметры URL), `body` (JSON для `POST`), для `GetOrderStatus` еще `path` (`{"id": ...}`) |
| АЛОР | глагол и путь из описания API: `"GET /md/v2/time"`, `"GET /md/v2/Clients/MOEX/D12345/summary"`, `"POST /commandapi/..."`. Глаголы `GET`, `POST`, `PUT`, `DELETE`. Каждый вызов тратит квоту по умолчанию | `query` (параметры URL), `body` (JSON), `request_id` (`X-REQID` команды: если не дать, коннектор сделает новый) |

Т-Банк и Финам говорят по gRPC. Описание всех сервисов и сообщений вшито в библиотеку, метод ищется в нем по имени, словарь становится
сообщением запроса, а ответ снова словарем. Поэтому годится **любой** метод API, в том числе тот, которого нет в общем интерфейсе. Формат
как у протокола брокера: 64-разрядные числа записаны строками (`"units": "274"`), время - строка RFC 3339, деньги Т-Банка -
`{"units": "274", "nano": 50000000}`, число Финама - `{"value": "100.05"}`. Имена полей в ответе - как в `.proto`. Лишнее поле в запросе
дает ошибку, а не молча пропадает.

БКС говорит по REST. Методы, которые библиотека знает по имени, лежат в таблице (глагол и путь), остальные вызываются как `"GET /путь"`
или `"POST /путь"`. Числа с дробной частью в ответе БКС приходят как `Decimal`, `float` в Python не попадает нигде.

## Что происходит при вызове

1. **Берется квота.** Имя метода ищется в файле лимитов брокера. Нет такого имени - тратится общее ведро (маршрут `"*"`). Бесплатно не уходит
   ни один вызов. Квоты нет - вызов **не отправляется**, и это `RateLimited` с `retry_after`. Счетчик общий с клиентом и с клиентами на том
   же `limiter=`: `raw` и `portfolio()` тратят одно ведро, если у них один маршрут.
2. **Идет вызов** с токеном клиента и его таймаутом.
3. **Ошибка брокера переводится** в те же исключения, что везде ([Ошибки](../errors.md)).

## Чтение и команда

- **`command=False`** (по умолчанию) - для чтения. Сетевой сбой и таймаут - `Transport`, вызов можно повторить.
- **`command=True`** - для всего, что **меняет счет**. Нет ответа (таймаут, обрыв, ошибка сервера) - `Unknown`: брокер мог выполнить команду.
  Библиотека такой вызов не повторяет. Как и `place`, команда доходит до конца, даже если вы перестали ее ждать (отмена задачи, таймаут).

Если сомневаетесь, меняет ли метод счет, ставьте `command=True`.

## Чего `raw` не делает

**`raw` обходит гарантии общего интерфейса.**

- Он **не знает про заявки клиента.** Заявка, поставленная через `raw`, не ведется коннектором как своя: ни учета «в пути», ни шлюза
  `reconcile`, ни проверок (шаг цены, лот, цена у стоп-лимита). Заявки ставьте `place` и `place_stop`. Через `raw` вызывайте то, чего в общем
  интерфейсе нет.
- Он не добавляет счет в ваш запрос: `account_id` кладите сами.
- **Потоки не отдаются.** Метод, который открывает поток (server-streaming), дает `Unsupported` с `capability == "raw_streaming"`. В Rust квота
  покрывает открытие, а поток читает ваш код. Python так передать не может. Потоки читайте общим интерфейсом (`subscribe_*`).
- Неизвестный метод и аргументы, которые не подходят методу, дают `Config`. Ничего не отправлено, квота не потрачена.
- У БКС и АЛОРа WebSocket-каналы через `raw` не открываются: это есть в Rust (`connect_ws`, у АЛОРа еще `connect_cws`), в Python нет.

## Как проверить

```bash
pytest crates/python/tests/test_raw.py
```

На имитации всех брокеров: чтение возвращает ответ словарем, неизвестный метод и лишнее поле отвергаются без отправки, потоковый метод
отвергается, квота тратится общая с интерфейсом и с соседним клиентом на том же `limiter`, команда с отказом брокера не становится `Unknown`.
