# Быстрый старт на Python

Цель страницы: за один заход дойти от пустого окружения до первой заявки и не рисковать деньгами по дороге. Ступеней три:
сначала имитация брокера в вашем процессе (без токена и без денег), потом песочница Т-Банка, и только потом боевой счет.

> **Боевой токен выдает человек, и первую боевую заявку ставят только с его слова.** ИИ-агент токен с правом торговли сам не создает и
> флаги записи (`BCS_IS_WRITE` и подобные) сам не включает: [правило 0](../agent-contract.md#правило-0-токен-и-первая-боевая-заявка-только-от-человека).
> На настоящем счете библиотеку пока не запускали, подробности: [Перед боевым счетом](../before-live.md).

## Шаг 1. Получить библиотеку

Нужен Python 3.10 или новее. Пакет `brokapi` ставится в виртуальное окружение:

```bash
python -m venv .venv && . .venv/bin/activate
pip install brokapi
```

Самая свежая версия из репозитория - вместо второй строки (нужен Rust 1.88 или новее, расширение собирается при установке,
это несколько минут. Подробности и частые ошибки - на странице [Установка](../install.md)):

```bash
pip install "git+https://github.com/runinfra/brokapi#subdirectory=crates/python"
```

Проверка:

```bash
python -c "import brokapi; print(brokapi.__version__)"
```

Должна напечататься версия `{{brokapi_version_py}}`. Не напечатала: таблица «Если что-то пошло не так» на странице
[Установка](../install.md#если-что-то-пошло-не-так).

## Шаг 2. Первая программа: без токена и без денег

Обычный скрипт. Имитация (`brokapi.testing.mock_tbank`) - это настоящий сервер на `127.0.0.1`, который говорит на протоколе Т-Банка, а
клиент к нему тот же `brokapi.Client`, что вернул бы `brokapi.connect("tbank", ...)`. Токен, счет и сеть не нужны.

Программа начинается с импортов:

```python
import asyncio
import sys
from decimal import Decimal

import brokapi
from brokapi.testing import mock_tbank
```

Сама работа - функция `first_order`. Она берет клиента любого брокера, поэтому дальше, на песочнице и на боевом счете, она не меняется:

```python
{{#include ../../../crates/python/examples/quickstart_tbank.py:first_order}}
```

Запуск на имитации: блок `async with` поднимает сервер и останавливает его в конце, `mock.connect()` возвращает клиента.

```python
{{#include ../../../crates/python/examples/quickstart_tbank.py:mock}}
```

Готовая программа целиком - в разделе «Вся программа» ниже (к этим кускам добавлены импорты и запуск через `asyncio.run`). Сохраните ее как
`quickstart_tbank.py` и запустите `python quickstart_tbank.py`. Должно напечататься:

```text
SBER: bid 273.9, ask 274, lot 10, price step 0.01
reconcile: 0 foreign order(s) on the account
placed: broker order id EX1, price 246.51
after cancel: Cancelled, orders alive: 0
the price stands still: bid 273.9
```

Что здесь произошло:

1. Котировка - верх стакана. Отдельного метода «котировка» у клиента нет: `order_book(sber, depth=1)` дает лучшую цену покупки и продажи.
2. Подписка на статусы своих заявок идет **до** `reconcile`, иначе событие между снимком сверки и подпиской пропало бы.
   `reconcile([])` открыл шлюз торговых команд: до него `place` вернул бы `NotReconciled`. Список пустой, потому что бот новый.
3. Цена заявки - 90% от лучшей покупки, округленная вниз до шага точной арифметикой (`round_to_step`). Количество - один лот, в штуках
   (лот `SBER` в имитации 10).
4. `cid` бот придумывает сам. В настоящем боте в этот момент строка уходит в журнал на диск: «отправляю».
5. `place` вернул `OrderAck`: «брокер принял». Что стало с заявкой, говорит `order_state`, и после `cancel` это `Cancelled`.

**Цена в имитации стоит на месте.** За стаканом нет рынка: сколько раз ни спроси, будет 273.9 и 274, а заявка сама не исполнится. Исполнить ее
просят у имитации: `mock.fill(cid)` ([Тесты против имитаций](testing.md#исполнить-заявку)). Поэтому на имитации проверяют порядок вызовов и разбор
исходов, а стратегию по движению цены на ней проверить нельзя. Имитация написана по документации брокера и не доказывает, что настоящий брокер
ответит так же.

Такие же имитации есть у БКС, Финама и АЛОРа (`mock_bcs()`, `mock_finam()`, `mock_alor()`), `first_order` работает на каждой.

## Шаг 3. Песочница Т-Банка

Следующая ступень - настоящий сервер брокера, но с игровыми деньгами. Нужны токен песочницы и счет песочницы. Токен выдает человек в кабинете
Т-Банка, как это сделать - в разделе «Вход» страницы [Т-Банк](../brokers/tbank.md#вход). Счет песочницы сам не появляется: его открывает метод
`OpenSandboxAccount` и пополняет `SandboxPayIn` (по документации Т-Банка). Без счета `connect` ответит `Config`: у токена нет открытого счета.

```bash
export TBANK_TOKEN=...        # токен песочницы
python quickstart_tbank.py sandbox
```

В коде меняется одна строка: клиента делает `connect`, а не имитация. `sandbox=True` выбирает адрес песочницы (без него адрес боевой, и токен песочницы
не подойдет), то же делает переменная `TBANK_SANDBOX=true`. Токен берется из окружения или из файла `.env` рядом с программой.

```python
{{#include ../../../crates/python/examples/quickstart_tbank.py:sandbox}}
```

Печатается то же самое, но с живыми ценами песочницы. Заявка покупает, поэтому на счете песочницы должны быть деньги: пополните его на сумму
больше цены лота. Если счетов у токена несколько, укажите нужный: `TBANK_ACCOUNT_ID` или `account_id=` в `connect`.

## Шаг 4. Боевой счет

Сюда идут, когда имитация и песочница прошли, а человек, чей это счет, сам выдал токен и сказал «можно». Первая заявка та же: лимитная, минимальное
количество, цена далеко от рынка, сразу отмена.

| Брокер | Подключение | Переменные |
|---|---|---|
| БКС | `await brokapi.connect("bcs")` | `BCS_REFRESH_TOKEN` (обязательно), `BCS_IS_WRITE` (`true` - токен на запись). Песочницы нет |
| Т-Банк | `await brokapi.connect("tbank")` | `TBANK_TOKEN`, `TBANK_ACCOUNT_ID` (если у токена несколько счетов), `TBANK_ENDPOINT`, `TBANK_APP_NAME`. Без `TBANK_SANDBOX` адрес боевой |
| Финам | `await brokapi.connect("finam")` | `FINAM_SECRET`, `FINAM_ACCOUNT_ID` (обязательно), `FINAM_API_URL`. Песочницы нет |
| АЛОР | `await brokapi.connect("alor")` | `ALOR_REFRESH_TOKEN` (обязательно), `ALOR_PORTFOLIO` (обязательно, если токен называет несколько портфелей), `ALOR_EXCHANGE` (`MOEX` или `SPBX`), `ALOR_TEST` (`true` - тестовый контур) |

Где взять токен и номер счета у каждого брокера: раздел «Вход» на страницах [БКС](../brokers/bcs.md#вход), [Т-Банк](../brokers/tbank.md#вход),
[Финам](../brokers/finam.md#вход), [АЛОР](../brokers/alor.md#вход). Первый день на Финаме, где песочницы нет:
[Финам](../brokers/finam.md#первый-день-на-финаме).

`await client.instrument("SBER")` у Т-Банка делает один запрос к справочнику и берет `uid` инструмента, у БКС, Финама и АЛОРа идентификатор строится
по тексту, второй аргумент задает площадку (`TQBR`, `MISX`). Особенности брокеров: [БКС](../brokers/bcs.md), [Т-Банк](../brokers/tbank.md),
[Финам](../brokers/finam.md), [АЛОР](../brokers/alor.md).

### Пример для БКС

У БКС нет песочницы, счет настоящий. Заявка ставится только по токену на запись, ее цена заведомо ниже рынка, количество минимальное, и она
снимается сразу. Токен без записи (`BCS_IS_WRITE` не `true`) дойдет только до чтения.

Настройки лежат в переменных окружения. Удобно файлом `.env` рядом с программой, пакет читает его сам. Токены не печатайте в логи и не кладите
в коммиты. Те же настройки можно передать аргументами: `brokapi.connect("bcs", refresh_token="...", write=True)`. Что не передано, берется из окружения.

`connect` поднимает два коннектора, рыночных данных и счета, и возвращает клиента. Если токен не подошел, это `Config` или `Transport` прямо здесь,
а не на первом запросе.

```python
{{#include ../../../crates/python/examples/quickstart_bcs.py:connect}}
```

Должно напечататься `connected: bcs-md and bcs-ud started`. Не напечатало: `Config` называет, какой настройки нет, `Transport` говорит, что БКС не
отвечает или отверг токен.

Чтение: три запроса, которые ничего не меняют. Инструмент `SBER` на основной площадке БКС (`TQBR`) получает метод `instrument`, он собирает
идентификатор по тикеру.

```python

```

Должно напечататься число балансов и позиций, лучшая цена покупки и продажи и число свечей. Цены и суммы здесь `Decimal`: цена печатается точной
десятичной записью, как ее отдал брокер, без хвостов вроде `0.30000000000000004`.

Дальше программа пишет в счет. Если токен не на запись, она остановится здесь.

```python

```

Заявка далеко от рынка и отмена. Порядок важен, причины каждого шага разобраны в [Круге жизни](../reconcile.md) и [Круге команд](../orders.md):

1. Правила инструмента: шаг цены и минимальное количество (`trading_params`). Метод заодно сообщает шаг цены коннектору, и цена не на
   шаге будет отвергнута сразу, до отправки.
2. Цена: 90% от лучшей покупки, округленная вниз до шага точной арифметикой (`round_to_step`).
3. Подписка на статусы своих заявок, и только потом `reconcile`: событие между снимком сверки и подпиской иначе потерялось бы.
4. `cid` придумывает бот. В настоящем боте здесь строка в журнал: «отправляю».
5. `place`, события статусов, `cancel` и проверка `order_state`.

```python
{{#include ../../../crates/python/examples/quickstart_bcs.py:order}}
```

Должно напечататься: `accepted: broker order id ...`, события `Acked`, затем `Cancelled`, в конце `order_state: Cancelled`.
Событие это уведомление, а доказательство - ответ `order_state`, поэтому программа не падает, если события не пришли.

Если `place` вернул `Rejected`, у ошибки есть `code`: `price_off_step` (цена не на шаге), `missing_price` (у лимитной заявки нет цены),
отказ брокера с его текстом. Если `Unknown`, заявка могла встать: не повторяйте, спросите `order_state(cid)`
([Если что-то пошло не так](../rust/recovery.md#place-вернул-unknown), общая логика одна для всех языков).

## Что произошло по шагам на БКС

1. `connect` поднял оба коннектора. У БКС, Финама и АЛОРа он сразу проходит авторизацию, поэтому неверный токен виден на этом шаге.
2. Чтение ничего не меняет и не требует сверки.
3. `subscribe_order_state` дал подписку на события своих заявок и вернулся, когда поток открыт. Она сделана до сверки нарочно.
4. `reconcile([])` открыл шлюз команд. До него `place` вернул бы `NotReconciled`.
5. `place` вернул `OrderAck`: «брокер принял». Статусы приходят событиями в `client.events`, порядок между ответом и событием не гарантирован.
6. `cancel` снял заявку, `close` остановил коннекторы.
